# Anime365 Downloader

Веб-приложение для домашнего сервера: смотреть каталог [Anime365](https://smotret-anime.org),
скачивать видео и субтитры по премиум-подписке и раскладывать их в существующую
медиатеку так, чтобы Jellyfin подхватил файлы как нужные серии нужного тайтла.

Ставится одним контейнером, работает на одном порту.

> Нужна **действующая премиум-подписка Anime365**. Без неё каталог и страницы
> тайтлов работают, а скачивание — нет: сервис отдаёт файлы только по токену.

## Что умеет

**Каталог.** Все 29 тысяч тайтлов лежат в локальной базе и обновляются по
расписанию, поэтому поиск и фильтры отвечают мгновенно и работают без сети.
Поиск по русскому, romaji и японскому названию; фильтры по жанрам, типу, году,
сезону, оценке; отдельная вкладка онгоингов.

**Страница тайтла.** Все переводы сведены в таблицу «язык × тип × автор» с
диапазонами покрытия серий («1–19, 22–25»), оценкой качества и пометкой
«вшитые субтитры / отдельный файл». Видно, чего не хватает локально.

**Скачивание.** Видео и субтитры по одному или пачкой, с выбором качества,
докачкой после обрыва, очередью, живым прогрессом и ретраями. Имена файлов
строятся по образцу соседей в целевой папке, чтобы медиасервер не потерял связь
серии с эпизодом.

**Библиотека.** Приложение обходит ваши папки, разбирает имена файлов и `.nfo`
и сопоставляет папки с тайтлами каталога — включая сезоны, спешлы и фильмы.
Что не сошлось, показывается отдельным списком и правится вручную.

**Просмотр.** Смотреть можно и онлайн через сервис, и уже скачанное — прямо в
браузере, с выбором дорожки и субтитров.

**Ещё:** извлечение звуковой дорожки в фонотеку · интеграция с Jellyfin
(обновление библиотеки, ссылки, коллекции, отчёт о нераспознанном) · три языка
интерфейса, светлая и тёмная тема · вход по логину и паролю, права на каждом
разделе.

## Установка

Нужны Docker и Docker Compose.

```bash
git clone git@github.com:bocchi-the-server/anime365.git
cd anime365
cp .env.example .env.app
```

Откройте `.env.app` и задайте минимум:

| Переменная | Что это |
|---|---|
| `A365_ACCESS_TOKEN` | токен Anime365 (см. ниже) |
| `A365_ADMIN_LOGIN` | имя учётной записи для входа в интерфейс |
| `A365_UI_PASSWORD` | пароль к ней |
| `A365_SERIES_ROOT` · `A365_MOVIES_ROOT` | пути к вашим библиотекам сериалов и фильмов |

Дальше:

```bash
docker compose up -d --build
```

Интерфейс — на `http://<адрес сервера>:8080`.

### Где взять токен

Войдите на сайт Anime365, откройте инструменты разработчика (F12) → Application
→ Cookies и скопируйте значение `access_token`. Токен бессрочный: относитесь к
нему как к паролю.

### Перед первым запуском: лимит inotify

Приложение следит за изменениями в библиотеке через inotify. Лимит на число
наблюдаемых каталогов общий для всей системы, и его же расходуют Jellyfin,
Sonarr и Radarr. На больших библиотеках стандартных 8192 не хватает.

```bash
sysctl fs.inotify.max_user_watches
```

Если меньше 200 000:

```bash
echo 'fs.inotify.max_user_watches=204800' | sudo tee /etc/sysctl.d/99-inotify.conf
sudo sysctl --system
```

Не хватило — приложение не сломается: оно перейдёт на сканирование по
расписанию и честно скажет об этом в интерфейсе.

## Настройка

Значения берутся из трёх слоёв, каждый следующий перекрывает предыдущий:

```
значение по умолчанию  <  переменная окружения  <  правка в интерфейсе
```

В интерфейсе у каждого поля видно, откуда взято текущее значение, и есть кнопка
сброса. Часть настроек помечена «только с сервера» — их из браузера не поменять
намеренно: это адреса, к которым ходит само приложение, и правка из браузера
открыла бы путь к чужим хостам.

Полный список переменных с пояснениями — в [`.env.example`](.env.example), он же
шаблон для `.env.app`. Подробности — в [docs/admin.md](docs/admin.md).

### Одна сеть с Jellyfin

Чтобы приложение ходило к Jellyfin по имени контейнера, а не по адресу хоста,
положите оба контейнера в общую сеть:

```bash
docker network create media
```

В compose-файле Jellyfin:

```yaml
services:
  jellyfin:
    networks: [media]

networks:
  media:
    external: true
```

В нашем `docker-compose.yml` раскомментируйте такой же блок `networks` и
добавьте сервису `networks: [media]`. После этого в `.env.app`:

```
A365_ENABLE_JELLYFIN=true
A365_JELLYFIN_URL=http://jellyfin:8096
A365_JELLYFIN_PUBLIC_URL=https://jellyfin.example.com
A365_JELLYFIN_API_KEY=<ключ из Jellyfin: Панель → API-ключи>
```

Адреса два, и это не дублирование: по первому ходит само приложение изнутри
docker-сети, по второму открываются ссылки в вашем браузере.

> ⚠️ **Если на хосте настроен прокси** (`HTTP_PROXY`, `ALL_PROXY`), имя соседнего
> контейнера обычно не входит в `NO_PROXY`, и запрос к Jellyfin уходит во внешний
> прокси: тот отвечает 503, а до Jellyfin не доходит ничего — в его логах при
> этом пусто. Приложение это учитывает и по умолчанию ходит к Jellyfin напрямую.
> Если ваш Jellyfin, наоборот, в интернете и доступен только через прокси,
> включите `A365_JELLYFIN_VIA_PROXY=true`.

## Безопасность

Приложение работает с вашим бессрочным премиум-токеном и пишет файлы в
медиатеку. **Не выставляйте его в интернет без внешней авторизации.**

Что сделано на нашей стороне: вход обязателен, пароль хранится хешем, есть
защита от перебора (счётчики по адресу и по имени, растущая задержка); токен
никогда не отдаётся наружу и не попадает в логи; адрес API выбирается из
серверного списка, а не из браузера; пути проверяются на выход за пределы
настроенных корней; заголовки CSP, проверка `Origin`, сессионная кука
`HttpOnly` + `SameSite=Strict`.

Рекомендуемая схема: слушать только локальную сеть или VPN. Если всё же наружу —
обратный прокси с HTTPS и внешней аутентификацией поверх встроенной.

Подробнее — [claude/07-security.md](claude/07-security.md).
