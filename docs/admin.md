# Установка и эксплуатация

Целевая платформа — Ubuntu Server в Docker. Ресурсы: около 200 МБ ОЗУ в покое,
до ~350 МБ при активной загрузке. База каталога занимает ~25 МБ на диске.

## Быстрый старт

```bash
git clone git@github.com:bocchi-the-server/anime365.git && cd anime365
```

```bash
cp .env.example .env
```

Дальше в `.env` минимально нужны три вещи:

```
A365_ACCESS_TOKEN=<токен аккаунта с премиум-подпиской>
A365_UI_PASSWORD=<пароль на вход>
A365_PUID=1000
A365_PGID=1000
```

`PUID`/`PGID` должны совпадать с владельцем медиабиблиотеки, иначе Jellyfin не
прочитает скачанное. Узнать их:

```bash
id -u && id -g
```

Пути к медиа правятся в `docker-compose.yml` (секция `volumes`) — левая часть это
путь на хосте, правая должна совпадать с `A365_SERIES_ROOT` и `A365_MOVIES_ROOT`.

⚠️ **Четыре корня обязаны быть непересекающимися:** `A365_SERIES_ROOT`,
`A365_MOVIES_ROOT`, `A365_AUDIO_ROOT`, `A365_DOWNLOAD_TMP`. Ни совпадать, ни
лежать один внутри другого они не могут. Контейнер **не запустится**, если это
нарушено, и напишет в лог, какая именно пара конфликтует:

```
Пути в настройках пересекаются, запуск невозможен:
  временная папка загрузок (/media/anime/tmp) лежит внутри корня сериалов (/media/anime)
```

Отказ жёсткий, потому что последствия чинятся только руками. Самый частый
случай — временная папка внутри библиотеки: сканер заводит недокачанные `.part`
как серии, а когда придёт настоящий файл, рядом остаётся дубль с привязкой на
мусор. Второй по частоте — фонотека внутри библиотеки: Jellyfin индексирует
звуковые файлы как видео без картинки. Отдельные корни ровно для этого и заведены.

Та же проверка срабатывает и при правке путей в UI — там она отвечает кодом
`PATHS_OVERLAP` и настройки не сохраняются.

```bash
docker compose up -d
```

UI поднимется на `http://127.0.0.1:8080`. Первый полный синк каталога занимает
около 32 секунд (44 запроса, ~29 тысяч тайтлов) и запускается автоматически.

## Настройки: три слоя

```
значение по умолчанию в коде  <  переменная окружения  <  правка в UI
```

Все настройки продублированы переменными вида `A365_<KEY>`. На странице настроек
у каждого поля видно, откуда взято действующее значение, и есть кнопка сброса
к переменной окружения или к значению по умолчанию.

`.env.example` генерируется из реестра настроек в коде, править его вручную
бессмысленно — он перезаписывается. Актуальную версию всегда можно скачать по
`GET /api/settings/env-example`.

Одно исключение: **список зеркал (`A365_MIRRORS`) меняется только на сервере**.
Из UI он показан, но недоступен для правки — это allowlist, по которому
проверяется `base_url`, и возможность дописать в него хост из браузера свела бы
защиту от SSRF к нулю.

## Переменные, которых нет в интерфейсе

Реестр настроек — про то, что пользователь меняет из браузера. Ниже другое:
вопросы эксплуатации сервера, которые задаёт тот, кто его держит.

### Сбор сведений о доступных переводах

Фоновая джоба обходит тайтлы и запоминает, какие типы перевода есть **на сайте**
(не в вашей библиотеке). Без неё не работает фильтр каталога «есть японские
субтитры»: серверного фильтра по типу перевода в API нет, и узнать это можно
только запросом на каждый тайтл.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `A365_TRANSLATION_SCAN_HOURS` | `24` | Период обхода в часах. `0` отключает джобу целиком |
| `A365_TRANSLATION_SCAN_RPM` | `30` | Запросов в минуту. Вдвое медленнее наблюдавшегося безопасного темпа |
| `A365_TRANSLATION_SCAN_SCOPE` | `library` | `library` — только привязанные к папкам тайтлы (сотни, минуты); `catalog` — весь каталог (29 тысяч, первый проход — часы) |

Темп считается отдельно от `A365_REQUEST_RATE_LIMIT`: тот про запросы, которых
ждёт человек, а фоновой джобе спешить некуда. На замере 300 тайтлов подряд при
30 запросах в минуту сайт не ограничил ни разу.

Джоба не запускается, пока идёт синхронизация каталога: обе ходят на сайт, и
одновременный старт удвоил бы частоту ровно тогда, когда её и держат низкой.

### Прокси и VPN

Стандартные переменные, те же, что понимают `curl` и `requests`. Через них идут
**все** исходящие запросы к Anime365: каталог, embed, скачивание файлов,
проксирование видео и субтитров в плеер.

| Переменная | Пример | Что делает |
|---|---|---|
| `HTTPS_PROXY` | `http://192.168.1.10:3128` | Прокси для https. Весь трафик к сайту такой, поэтому обычно достаточно её одной |
| `HTTP_PROXY` | `http://192.168.1.10:3128` | Прокси для http |
| `ALL_PROXY` | `socks5h://192.168.1.10:1080` | Все схемы сразу; сюда пишут SOCKS5 |
| `NO_PROXY` | `localhost,127.0.0.1` | Исключения через запятую |

Для SOCKS предпочтительно `socks5h://`, а не `socks5://`: буква `h` означает
разрешение имён на стороне прокси. Без неё DNS-запросы уйдут мимо VPN, и
блокировка по имени останется в силе.

Включать ничего не нужно — достаточно задать адрес. `docker-compose.yml`
пробрасывает эти переменные с хоста, так что один и тот же compose работает и с
VPN, и без него. При старте в лог пишется, через что пойдут запросы; логин и
пароль в адресе прокси маскируются.

Если задан SOCKS, но в образе нет пакета `socksio`, приложение скажет об этом
при старте отдельной строкой уровня ERROR, а не будет молча падать на каждом
запросе к сайту.

## Доступ снаружи

Порт публикуется как `127.0.0.1:8080:8080`. Так и надо оставить. Через UI
доступен ваш бессрочный премиум-токен и запись в файловую систему сервера —
выставлять это в интернет напрямую нельзя.

Варианты доступа с других устройств, по возрастанию риска:

1. **VPN** (Tailscale, WireGuard) — рекомендуемый. Ничего не публикуется вовсе.
2. **Локальная сеть**: замените публикацию порта на `0.0.0.0:8080:8080`.
   Пароль на UI при этом обязателен.
3. **Наружу через Nginx** — только с HTTPS, внешней аутентификацией
   (Authelia / basic auth) **в дополнение** к встроенному паролю, и с fail2ban.

Встроенная защита: пароль хранится argon2-хешем, попытки входа ограничены
(10 за 5 минут на адрес) и на каждой неудаче добавляется секундная пауза; кука
сессии `HttpOnly` + `SameSite=Strict`; изменяющие запросы проверяются по
`Sec-Fetch-Site`/`Origin`; отдаётся CSP без `unsafe-inline` для скриптов.

Пароль можно задать двумя способами. `A365_UI_PASSWORD` в `.env` — открытым
текстом (иначе пришлось бы хешировать руками). Заданный через UI — хранится
хешем. При смене пароля все сессии сбрасываются, кроме текущей.

## Библиотека только для чтения

Если библиотеку смонтировать `:ro`, приложение это увидит и пометит корень как
недоступный для записи: каталог, сопоставление и значки наличия продолжат
работать, а загрузки в этот корень будут отклонены с внятной ошибкой, а не
падать при перемещении файла.

## Обслуживание

Бэкап — это копия `./data` (SQLite в режиме WAL) и `./config`. Останавливать
контейнер для копирования не обязательно, но чище:

```bash
docker compose stop && cp -a data data.bak && docker compose start
```

Логи ротируются докером (3 файла по 10 МБ). Секреты из них вырезаются фильтром:
токен не попадает ни в сообщения, ни в тексты ошибок.

Обновление:

```bash
git pull && docker compose up -d --build
```

Схема БД дополняется на месте при старте — миграции вручную запускать не нужно.
Каталог это кэш, его в худшем случае можно пересобрать заново кнопкой
«обновить сейчас».

## Jellyfin

Интеграция за тумблером `A365_ENABLE_JELLYFIN`, по умолчанию выключена. Делает
две вещи: просит Jellyfin пересканировать библиотеку после раскладки файлов и
показывает на странице тайтла кнопку «Смотреть в Jellyfin».

**Адресов два, и это не перестраховка.** `/System/Info/Public` живого сервера
отдаёт свой внутренний адрес, который снаружи недоступен, а публичное имя за
обратным прокси не резолвится изнутри docker-сети. Одним адресом обе роли не
покрыть:

| Переменная | Пример | Для чего |
|---|---|---|
| `A365_JELLYFIN_URL` | `http://jellyfin:8096` | Куда ходит приложение |
| `A365_JELLYFIN_PUBLIC_URL` | `https://jellyfin.example.com` | Куда ведут ссылки в браузере |
| `A365_JELLYFIN_API_KEY` | — | Ключ, см. ниже |

⚠️ **Оба адреса задаются только на сервере** и из интерфейса не меняются — так
же, как allowlist зеркал. Причины разные, но обе серьёзные. Внутренний адрес это
то, куда приложение ходит само, изнутри сети сервера: правка из браузера
превратила бы его в инструмент опроса внутренних хостов, да ещё и с возвратом
ответа в интерфейс. Публичный адрес приложение не запрашивает, но подставляет в
кнопку, на которую жмут, — подмена увела бы людей на чужой хост под видом
вашего Jellyfin.

Публичный можно не задавать: если он пуст, берётся внутренний. Это обычный
случай, когда Jellyfin не за прокси.

Во внутреннем адресе держите **имя контейнера**, а не IP: адрес в docker-сети
переживёт не каждый перезапуск. Оба контейнера должны быть в одной сети.

**Ключ** заводится в самом Jellyfin: Панель управления → Дополнительно →
API-ключи → плюс. Кладите его в `.env`, а не в интерфейс, если не хотите
держать секрет в базе. Приложение обрезает пробелы и перенос строки, а ключ с
не-ASCII символами отклоняет с внятной причиной — вставленный мышью не тот
текст иначе давал бы невнятный сбой соединения.

Проверить связку целиком можно кнопкой в настройках: она делает настоящий
запрос и различает «недоступен», «не принял ключ» и «ответил ошибкой».

### Как тайтл находится в Jellyfin

Сопоставлением **по пути**, а не по названию и не по внешнему ID. Фильтра по
AniList или Shikimori у Jellyfin нет вовсе (проверено на спецификации 10.11.8),
а сравнение названий давало бы те же промахи, что и любой нечёткий матчинг.

Вместо этого сравниваются **хвосты путей**: папку тайтла мы знаем из своего
скана, Jellyfin отдаёт свой `Path`. Точки монтирования разные, структура под
ними одна. Настраивать трансляцию путей не нужно.

Отсюда следствие: кнопка не появится, пока Jellyfin не увидел папку. Если
только что скачали — дайте ему пересканировать. Список элементов кэшируется на
пять минут; правка настроек Jellyfin сбрасывает кэш сразу.

Проверено на живой библиотеке (433 элемента, 2215 файлов): все шесть папок
эталонного набора сопоставились, включая `Specials`.

### Что Jellyfin не распознал

Библиотека → вкладка **Jellyfin** → «Сверить с Jellyfin». Показывает файлы,
которые видит наш сканер, а Jellyfin у себя не подобрал — почти всегда это
значит, что не подошло именование. Своего ответа на такой вопрос у Jellyfin нет:
он не сообщает, что пропустил, он просто этого не показывает. Считается
разностью множеств на нашей стороне.

Сводка по папкам идёт первой намеренно: нераспознанное почти всегда идёт
группами по одной причине, и видна она по папке, а не по списку имён.

Запускается кнопкой, а не при открытии вкладки: запрос обходит библиотеку
Jellyfin целиком.

Если Jellyfin не ответил, отчёт так и скажет. Он **не** покажет «не распознано
всё» — это была бы ложная тревога, по которой пошли бы переименовывать файлы.

## Пользователи и права

Настройки → Пользователи. Права: **Настройки** (через них виден премиум-токен и
задаются пути записи), **Загрузки**, **Библиотека**, **Просмотр**.

Проверка серверная — спрятанная в интерфейсе кнопка ограничением не является.

Пока все заведённые пользователи администраторы, разграничение ни на что не
влияет, и панель об этом прямо говорит. Оно включается, как только появится хотя
бы один обычный пользователь.

Последнего администратора нельзя ни разжаловать, ни удалить: иначе управлять
правами станет некому, и чинить пришлось бы правкой базы.

Пароль у пользователя необязателен: пока вход общий (`A365_UI_PASSWORD`), он не
используется. Поле есть, чтобы не заводить пароли вторым заходом.

## Расписания

| Что | По умолчанию | Стоимость |
|---|---|---|
| Инкрементальный синк + онгоинги | раз в час | секунды |
| Полный рескан каталога | раз в 24 часа | ~32 с, 44 запроса |
| Сверочный скан библиотеки | раз в 24 часа | зависит от размера |

Библиотека в основном обновляется не по расписанию, а по событиям файловой
системы (inotify): файлы появляются в UI через несколько секунд после
копирования. Сверочный скан — страховка на случай пропущенных событий.

⚠️ На NFS и SMB inotify не работает: события от других хостов не доставляются.
Приложение это определяет, откатывается на расписание и **пишет об этом на
странице библиотеки**. Если у вас сетевая ФС — уменьшите `A365_LIBRARY_SCAN_HOURS`
до 4–6.

Если в логе появилось предупреждение про `max_user_watches`, поднимите лимит:

```bash
echo 'fs.inotify.max_user_watches=204800' | sudo tee /etc/sysctl.d/60-inotify.conf && sudo sysctl --system
```

## Диагностика

| Симптом | Причина и что делать |
|---|---|
| Видео скачалось на ~150 КБ вместо сотен МБ | Подписка неактивна или токен неверен — вместо файла приходит HTML. Проверьте кнопкой «Проверить токен» в настройках |
| Загрузки падают, каталог работает | Зеркало заблокировано. Смените `base_url` в настройках — ссылки скачивания переписываются на выбранное зеркало |
| Jellyfin не видит скачанное | Не совпали `PUID`/`PGID`. Проверьте владельца файлов в целевой папке |
| «Нет доступного корня библиотеки» | Том не смонтирован или смонтирован `:ro`. Смотрите статус корней на странице библиотеки |
| Папки не привязываются | Смотрите «нераспознанные папки». Порог нечёткого совпадения настраивается; всё, что попало в серую зону, ждёт подтверждения, а не мапится молча |
| 429 при работе | Сработал ограничитель частоты на дорогих эндпоинтах. Обычно это залипшая вкладка — перезагрузите страницу |
