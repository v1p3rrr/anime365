# Для разработки

## Локальный запуск

Бэкенд:

```bash
cd backend && pip install -e ".[dev]" && uvicorn app.main:app --reload --port 8080
```

Фронтенд (Vite проксирует `/api` на 8080):

```bash
cd frontend && npm install && npm run dev
```

`npm run build` кладёт статику прямо в `backend/app/static`, откуда её раздаёт
FastAPI. Отдельного контейнера с Nginx нет намеренно: это лишние 30 МБ образа и
ещё один конфиг ради раздачи трёх файлов.

Тесты:

```bash
cd backend && python -m pytest -q
```

## Данные для проверки: папка `temp/`

В `temp/` лежат **настоящие** данные пользователя, а не синтетика. Она в
`.gitignore` и в репозиторий не идёт. Это не мусор и не остатки отладки — на
этом проверяются вещи, которые на выдуманных файлах не ломаются.

| Что | Объём | Для чего годится |
|---|---|---|
| `YuruYuri - Happy Go Lily/` | Season 1–3 + `Specials/` | Сезоны как отдельные `series_id`; `<anilistid>` есть только у 1-го сезона, а `<shikimoriid>` содержит мусор (указывает на другое аниме) — то есть сезоны 2–3 обязаны вытягиваться строковым каскадом. `Specials/` проверяет отсечение по `<season>0</season>` |
| `Zombie Land Saga/` | Season 2 | Сиквел как отдельный тайтл (`Revenge`) |
| `tree.txt` | 11 364 строки | Полная выгрузка библиотеки сериалов. Скармливается в `POST /api/library/parse-test` — на нём мерялся парсер имён |
| `tree_movies.txt` | 524 строки | То же для библиотеки фильмов |

Всего 49 `.mkv`, 56 `.nfo`, 56 `.srt`, 13 ГБ. Важно, что файлы **настоящие**, а
не пустышки: `.mkv` пригодны для ffprobe, а `.nfo` — с реальными
`<streamdetails>`, `<premiered>` и внешними ID, включая известные аномалии
(у Fate HF I язык видеодорожки записан как `ita`).

Из-за размера прогон по ним не входит в `pytest` и запускается руками, когда
меняется что-то из: сканер библиотеки, парсер имён, разбор `.nfo`, определение
дорожек, каскады матчинга.

## Правила, которые легко нарушить не заметив

**Настройки объявляются только в `core/settings_registry.py`.** Из этого реестра
генерируются парсинг переменных окружения, форма в UI и `.env.example`. Объявить
настройку в двух местах — гарантированно получить расхождение слоёв через месяц.
Читать значения только через `settings.get(...)`; прямое обращение к `os.environ`
в остальном коде запрещено.

**Секреты не попадают в репозиторий.** Ни в тесты, ни в фикстуры, ни в примеры.
В тестах используются синтетические значения. Подробности — в
`claude/07-security.md`, правило №0.

**`token_sort_ratio`, а не `token_set_ratio`.** Второй считает подстроку полным
совпадением: «zombie» против «zombie land saga» даёт 100, и каталог начинает
склеивать разные тайтлы.

**Запись в файловую систему проходит через `core/paths.resolve_within()`.**
Имя автора перевода приходит из внешнего API и попадает в имя файла — это
недоверенный ввод. Санитизация отдельных компонентов имени есть, но проверка
итогового пути обязательна отдельно.

**Файлы libass лежат в `public/libass/`, а не в бандле.** Их раскладывает
`frontend/scripts/copy-libass.mjs` на шаге `prebuild`. Причина: SubtitlesOctopus
грузит `.wasm` относительно воркера, а Vite переименовывает ассеты в хешированные
имена — воркер искал бы файл, которого нет. Отказ при этом молчаливый: ни ошибки,
ни записи в консоль. Не переводите это на обычный импорт.

**Адрес субтитров обязан оканчиваться на `.ass`.** Плагин плеера определяет формат
по расширению (`getExt(url) === 'ass'`). Для этого заведён маршрут
`/api/stream/{id}/subtitles.ass` рядом со старым.

**Мутаций по GET нет.** Это часть защиты от CSRF, а не стилистика.

**Корни библиотек не должны пересекаться, и это проверяется дважды.**
`settings_registry.check_path_layout()` вызывается и при сохранении настроек
(код ошибки `PATHS_OVERLAP`), и при старте в `bootstrap()`. Второе — не
дублирование: значение может прийти из `docker-compose`, минуя UI, и такой
запуск обязан падать. Добавляете новый путь в настройках — впишите его ключ в
`PATH_KEYS` и оба словаря подписей, иначе он выпадет из проверки молча.

**Новый эндпоинт закрыт по умолчанию.** Авторизация висит middleware, а не
зависимостью роутера: список исключений в `core/middleware.PUBLIC_PATHS`
явный и короткий. Добавлять туда что-то — осознанное решение.

**FTS5-запросы собираются `services/fts.build_query()`.** Пользовательская строка
не склеивается в MATCH-выражение: кавычки и операторы FTS ломают запрос, а в
худшем случае меняют его смысл.

**Пагинация каталога двухшаговая.** `/catalog/ids` отдаёт только идентификаторы
(29 тысяч ≈ 200 КБ), `/catalog/cards` — окно карточек. Не превращайте это в
обычную страничную пагинацию: виртуальному списку нужна полная длина сразу.

## Особенности API Anime365, о которые уже спотыкались

Полный разбор — в `claude/02-api-findings.md`. Самое опасное:

- `GET /api/series` **без `fields` отдаёт всё**, включая описания и эпизоды —
  мегабайты на страницу.
- Пагинация переводов через `afterId` **врёт без `feed=id`**: выдача не
  отсортирована, и вторая страница приходит пустой.
- `episodeType` обязателен к проверке: трейлеры лежат вперемешку с сериями и
  имеют собственный `episodeInt: "1"`.
- `numberOfEpisodes` — это **запланированное** число серий, а не выложенное.
- Ссылки скачивания требуют `access_token` **в URL**. Без него приходит
  HTML-страница с кодом 200 — поэтому в загрузчике стоит проверка `content-type`.
- `embed` всегда возвращает ссылки на `smotret-anime.org`, к какому бы зеркалу вы
  ни обращались. Хост переписывается на выбранный (`rewrite_host`).
- Ступени качества нелинейны: у источника 528p в `download` бывает 720p, у 2160p
  максимум — 1080p. Из `height` их вывести нельзя, только из `embed`.
- Списков просмотренного в API нет вообще: `/api/me/watching` и подобные
  возвращают тот же объект, что `/api/me` — роутер игнорирует хвост пути.

## Схема БД

`create_all` при старте плюс дописывание недостающих колонок
(`core/migrations.add_missing_columns`). Alembic не заведён сознательно: схема
меняется редко, а каталог это кэш, который в крайнем случае пересобирается.
Появятся несовместимые изменения — заводите Alembic, но не раньше.

Многопользовательность заложена, но выключена: таблица `app_user` существует с
единственной строкой, у пользовательских сущностей есть `created_by_user_id`,
сессия несёт `user_id`. Включение аккаунтов не потребует менять схему.

## Роли

`core/permissions.py`: `Permission` (`SETTINGS`, `DOWNLOADS`, `LIBRARY`,
`WATCH`), `CurrentUser.can()`, зависимости `require()` и `require_admin()`.
Проверка **серверная** — прятать кнопку в UI недостаточно, эндпоинт обязан
отказывать сам.

Поведение сейчас: пользователь один, он администратор, и с точки зрения UI
ничего не изменилось. Форма управления пользователями есть в настройках; правки
и удаления копятся в черновике и применяются кнопкой — права слишком критичны,
чтобы менять их случайным кликом.

Две ловушки, обе уже стреляли:

- **Новая колонка роли не появляется у существующих строк сама.**
  `add_missing_columns()` дописывает колонку, но значение по умолчанию из модели
  применяется при вставке, а не задним числом. Без backfill в `bootstrap()`
  единственный пользователь на работающей установке перестал бы быть
  администратором и запер бы сам себя. Backfill есть — не удаляйте его.
- **Когда пароль не задан, действует `_FALLBACK`-администратор.** Иначе установка
  без пароля закрыла бы сама себя от настройки.
