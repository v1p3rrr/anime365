## Локальный запуск

Бэкенд:

```bash
cd backend && pip install -e ".[dev]" && uvicorn app.main:app --reload --port 8080
```

Фронтенд (Vite проксирует `/api` на 8080):

```bash
cd frontend && npm install && npm run dev
```

`npm run build` кладёт статику прямо в `backend/app/static`, откуда её раздаёт
FastAPI. Отдельного контейнера с Nginx нет намеренно: это лишние 30 МБ образа и
ещё один конфиг ради раздачи трёх файлов.

Тесты:

```bash
cd backend && python -m pytest -q
```

## Данные для проверки: папка `temp/`

В `temp/` лежат **настоящие** данные пользователя, а не синтетика. Она в
`.gitignore` и в репозиторий не идёт. Это не мусор и не остатки отладки — на
этом проверяются вещи, которые на выдуманных файлах не ломаются.

| Что | Объём | Для чего годится |
|---|---|---|
| `YuruYuri - Happy Go Lily/` | Season 1–3 + `Specials/` | Сезоны как отдельные `series_id`; `<anilistid>` есть только у 1-го сезона, а `<shikimoriid>` содержит мусор (указывает на другое аниме) — то есть сезоны 2–3 обязаны вытягиваться строковым каскадом. `Specials/` проверяет отсечение по `<season>0</season>` |
| `Zombie Land Saga/` | Season 2 | Сиквел как отдельный тайтл (`Revenge`) |
| `tree.txt` | 11 364 строки | Полная выгрузка библиотеки сериалов. Скармливается в `POST /api/library/parse-test` — на нём мерялся парсер имён |
| `tree_movies.txt` | 524 строки | То же для библиотеки фильмов |

Всего 49 `.mkv`, 56 `.nfo`, 56 `.srt`, 13 ГБ. Важно, что файлы **настоящие**, а
не пустышки: `.mkv` пригодны для ffprobe, а `.nfo` — с реальными
`<streamdetails>`, `<premiered>` и внешними ID, включая известные аномалии
(у Fate HF I язык видеодорожки записан как `ita`).

Из-за размера прогон по ним не входит в `pytest` и запускается руками, когда
меняется что-то из: сканер библиотеки, парсер имён, разбор `.nfo`, определение
дорожек, каскады матчинга.

## Правила, которые легко нарушить не заметив

**Настройки объявляются только в `core/settings_registry.py`.** Из этого реестра
генерируются парсинг переменных окружения, форма в UI и `.env.example`. Объявить
настройку в двух местах — гарантированно получить расхождение слоёв через месяц.
Читать значения только через `settings.get(...)`; прямое обращение к `os.environ`
в остальном коде запрещено.

**Секреты не попадают в репозиторий.** Ни в тесты, ни в фикстуры, ни в примеры.
В тестах используются синтетические значения. Подробности — в
`claude/07-security.md`, правило №0.

**`token_sort_ratio`, а не `token_set_ratio`.** Второй считает подстроку полным
совпадением: «zombie» против «zombie land saga» даёт 100, и каталог начинает
склеивать разные тайтлы.

**Запись в файловую систему проходит через `core/paths.resolve_within()`.**
Имя автора перевода приходит из внешнего API и попадает в имя файла — это
недоверенный ввод. Санитизация отдельных компонентов имени есть, но проверка
итогового пути обязательна отдельно.

**Файлы libass лежат в `public/libass/`, а не в бандле.** Их раскладывает
`frontend/scripts/copy-libass.mjs` на шаге `prebuild`. Причина: SubtitlesOctopus
грузит `.wasm` относительно воркера, а Vite переименовывает ассеты в хешированные
имена — воркер искал бы файл, которого нет. Отказ при этом молчаливый: ни ошибки,
ни записи в консоль. Не переводите это на обычный импорт.

**Адрес субтитров обязан оканчиваться на `.ass`.** Плагин плеера определяет формат
по расширению (`getExt(url) === 'ass'`). Для этого заведён маршрут
`/api/stream/{id}/subtitles.ass` рядом со старым.

**Мутаций по GET нет.** Это часть защиты от CSRF, а не стилистика.

**Правили `.md` — запустите `python scripts/update_docs_toc.py`.** У каждого
документа сверху таблица «строка → раздел», по ней документацию читают кусками;
любая вставленная строка сдвигает номера ниже неё, и оглавление начинает молча
уводить не туда. Руками номера не правят. Расхождение ловит
`tests/test_docs_toc.py` — он же проверяет, что все ссылки `](#…)` куда-то ведут.

**Пишущая транзакция должна быть короткой.** Писатель у SQLite один: пока
транзакция открыта, все остальные стоят, а на десятой секунде получают
«database is locked» (`busy_timeout=10000`). Это не теория — на сервере так
падали загрузки и синхронизация каталога.

Три правила, все закреплены тестами (`test_db_locking.py`,
`test_transaction_hygiene.py`):

- **никаких `await` внутри `session_scope()`** — сетевой запрос длится секунды,
  и всё это время база занята;
- **тяжёлые вычисления снаружи.** Схема «короткое чтение → счёт без базы →
  короткие записи порциями». Так устроен `_map_folders`: раньше нечёткое
  сопоставление крутилось под открытой транзакцией и держало лок 0,12 с на
  папку, то есть две минуты на тысяче папок;
- **длинную работу — порциями, с паузой между ними.** Пересборка FTS идёт по
  500 тайтлов с паузой 10 мс. Без паузы поток забирает лок обратно мгновенно, и
  ждущий сосед всё равно стоит секундами (замер: 5,1 с против 0,2 с).

**Таблица `series` широкая — не доходите до её строк.** JSON-колонки дают около
25 МБ на 29 тысяч строк, поэтому любое обращение к строке стоит секунду
независимо от того, сколько полей вы выбираете. Запросы каталога обязаны
попадать в **покрывающие** индексы, и это проверяется тестом
`test_catalog_indexes.py` через `EXPLAIN QUERY PLAN`.

Правило устройства индексов: `is_hentai` — ведущая, дальше колонка сортировки,
дальше `id` и **все фильтруемые колонки**. Последнее и есть суть: человек
фильтрует по одному полю, а сортирует по другому, и недостающую колонку SQLite
дочитает из таблицы. Так фильтр по сезону с сортировкой по оценке стоил 4,7 с
([D-84](../claude/09-decisions.md)).

**Индекс каталога называется явно** — `INDEXED BY` по таблице `SORT_INDEX` в
`api/catalog.py`. Не потому, что планировщику не доверяют вообще, а потому, что
при равной оценке стоимости он выбирает по-разному на разных версиях SQLite:
локальная 3.49 и контейнерная 3.46 расходятся на одних и тех же запросах.
Добавили сортировку — добавьте запись в `SORT_INDEX`, иначе запрос упадёт;
добавили фильтр — допишите колонку во все четыре индекса и строку в тест.

Три вещи, которые легко «починить» обратно: лишний индекс делает медленнее
(узкие индексы под фильтр планировщик предпочитал покрывающим — батарея 211 мс
против 145), `ANALYZE` не запускается намеренно (с ним один запрос
деградировал в 180 раз), а прогонять надо **всю** батарею, а не свой один запрос.

**Индекс не появится и не изменится в существующей базе сам.** `create_all`
создаёт индексы только вместе с новой таблицей, а индекс с уже занятым именем не
переопределяет вовсе. За это отвечает `sync_indexes()` в `core/migrations.py`:
создаёт недостающие, пересоздаёт те, у которых поменялся набор колонок, а
`drop_obsolete_indexes()` убирает отжившие. Ловушка та же, что с колонками,
только дороже: всё продолжит работать, просто в тысячу раз медленнее.

**В `series_fts` идентификатор тайтла — это `rowid`.** Колонка `series_id` там
есть, но она неиндексируемая, то есть лежит в содержимом записи: на 7525
совпадениях `rowid` читается за 2,4 мс, а `series_id` — за 243 мс. `ORDER BY
rank` не используем вовсе — FTS5 считает BM25 по всем совпадениям сразу (459 мс),
а порядок выдачи всё равно задаёт пользователь.

**Большой список идентификаторов не передаётся параметрами.** Пять тысяч значений
в `IN (…)` через SQLAlchemy — это 900 мс на сборку выражения при 0,6 мс на самом
запросе. Такие списки подставляются в текст запроса числами (`fts.match_condition`),
и это безопасно ровно потому, что там только `int` из нашей же базы.

**Корни библиотек не должны пересекаться, и это проверяется дважды.**
`settings_registry.check_path_layout()` вызывается и при сохранении настроек
(код ошибки `PATHS_OVERLAP`), и при старте в `bootstrap()`. Второе — не
дублирование: значение может прийти из `docker-compose`, минуя UI, и такой
запуск обязан падать. Добавляете новый путь в настройках — впишите его ключ в
`PATH_KEYS` и оба словаря подписей, иначе он выпадет из проверки молча.

**Новый эндпоинт закрыт по умолчанию.** Авторизация висит middleware, а не
зависимостью роутера: список исключений в `core/middleware.PUBLIC_PATHS`
явный и короткий. Добавлять туда что-то — осознанное решение.

**FTS5-запросы собираются `services/fts.build_query()`.** Пользовательская строка
не склеивается в MATCH-выражение: кавычки и операторы FTS ломают запрос, а в
худшем случае меняют его смысл.

**Пагинация каталога двухшаговая.** `/catalog/ids` отдаёт только идентификаторы
(29 тысяч ≈ 200 КБ), `/catalog/cards` — окно карточек. Не превращайте это в
обычную страничную пагинацию: виртуальному списку нужна полная длина сразу.

## Особенности API Anime365, о которые уже спотыкались

Полный разбор — в `claude/02-api-findings.md`. Самое опасное:

- `GET /api/series` **без `fields` отдаёт всё**, включая описания и эпизоды —
  мегабайты на страницу.
- Пагинация переводов через `afterId` **врёт без `feed=id`**: выдача не
  отсортирована, и вторая страница приходит пустой.
- `episodeType` обязателен к проверке: трейлеры лежат вперемешку с сериями и
  имеют собственный `episodeInt: "1"`. Значений одиннадцать, а не пять
  заявленных: кроме `preview` контентом не являются `opening`, `ending`,
  `other`, `menu`.
- `isActive: 0` у эпизода — **заготовка**, заведённая сайтом впрок. Переводов у
  таких нет ни у одной (проверено на 710 эпизодах). У «Врат» под первым куром
  24 записи при плане 12.
- `numberOfEpisodes` — это **запланированное** число серий, а не выложенное.
- Ссылки скачивания требуют `access_token` **в URL**. Без него приходит
  HTML-страница с кодом 200 — поэтому в загрузчике стоит проверка `content-type`.
- `embed` всегда возвращает ссылки на `smotret-anime.org`, к какому бы зеркалу вы
  ни обращались. Хост переписывается на выбранный (`rewrite_host`).
- Ступени качества нелинейны: у источника 528p в `download` бывает 720p, у 2160p
  максимум — 1080p. Из `height` их вывести нельзя, только из `embed`.
- Списков просмотренного в API нет вообще: `/api/me/watching` и подобные
  возвращают тот же объект, что `/api/me` — роутер игнорирует хвост пути.

## Схема БД

`create_all` при старте плюс дописывание недостающих колонок
(`core/migrations.add_missing_columns`). Alembic не заведён сознательно: схема
меняется редко, а каталог это кэш, который в крайнем случае пересобирается.
Появятся несовместимые изменения — заводите Alembic, но не раньше.

Многопользовательность заложена, но выключена: таблица `app_user` существует с
единственной строкой, у пользовательских сущностей есть `created_by_user_id`,
сессия несёт `user_id`. Включение аккаунтов не потребует менять схему.

## Кеш на клиенте

Кеша два, и путать их не надо.

**Данные API** — TanStack Query, в памяти вкладки. `staleTime` 60 секунд (когда
перезапрашивать), `gcTime` 30 минут (когда выбрасывать неиспользуемое). Второе
важнее, чем кажется: по умолчанию TanStack выбрасывает данные через **пять**
минут, и человек, ушедший в очередь на десять минут, возвращался на пустую
страницу тайтла.

⚠️ **Всё, что должно переживать переход между страницами, обязано лежать в кеше
запросов, а не в состоянии компонента.** Карточки каталога когда-то копились в
`useState<Map>` — и умирали вместе с размонтированием страницы, из-за чего
каталог грузился заново при каждом возврате. Теперь окна карточек это обычные
запросы (`useQueries` в `useVirtualCatalog`), ключ — сами идентификаторы окна.

**Личные настройки** — `localStorage` под версионированным префиксом: язык,
тема, типы переводов, режим листания. Они не про данные, а про вкусы, и на
сервер не уходят вовсе.

Персистентного кеша (IndexedDB) нет намеренно: после индексов первый заход стоит
миллисекунды, повторные закрыты кешем в памяти, и переживать перезагрузку
вкладки было бы не за что платить ([D-82](../claude/09-decisions.md)).

## Роли

`core/permissions.py`: `Permission` (`CATALOG`, `WATCH`, `DOWNLOADS`, `LIBRARY`,
`SETTINGS`), `CurrentUser.can()`, зависимости `require()` и `require_admin()`.
Проверка **серверная** — прятать кнопку в UI недостаточно, эндпоинт обязан
отказывать сам. Полная таблица «право → эндпоинты → что прячется в интерфейсе» —
в `docs/admin.md`.

**Каждый** маршрут под `/api/` спрашивает право; исключений ровно пять, и все
перечислены в `tests/test_permissions_audit.py`. Тест проверяет это двумя
способами сразу: разбором декораторов в `app/api/*.py` и обходом уже собранного
приложения (`app.routes`) — второй ловит маршруты, объявленные не в роутерах,
например `/api/docs` прямо в `main.py`.

На фронте то же самое даёт хук `hooks/usePermissions.ts`. Два правила, оба
неочевидны:

- **пока ответ `/api/users/me` не пришёл, `can()` отвечает утвердительно.** Иначе
  интерфейс мигал бы пустотой на каждой загрузке. Там, где мигание недопустимо
  (страница целиком, запрос за настройками), ждём флага `ready`;
- **прячем, а не отключаем.** Кнопка, отвечающая отказом, читается как поломка.
  Исключение — состояние, которое полезно видеть и без права: «фильм или сериал»
  без `library` остаётся значком, а не пропадает.

Форма управления пользователями — в настройках, только для администратора;
правки и удаления копятся в черновике и применяются кнопкой.

Две ловушки, обе уже стреляли:

- **Новая колонка роли не появляется у существующих строк сама.**
  `add_missing_columns()` дописывает колонку, но значение по умолчанию из модели
  применяется при вставке, а не задним числом. Без backfill в `bootstrap()`
  единственный пользователь на работающей установке перестал бы быть
  администратором и запер бы сам себя. Backfill есть — не удаляйте его.
- **Когда пароль не задан, действует `_FALLBACK`-администратор.** Иначе установка
  без пароля закрыла бы сама себя от настройки.
