# Anime365 API — проверенные факты

Всё ниже получено **реальными запросами** к API (не из документации), `User-Agent: Anime365Downloader`.
Дата проверки: 2026-07-29. Спарсенный Swagger лежит в `../anime365-api.md` — он местами неполон
и в одном месте прямо говорит «формат не задокументирован».

---

## Аккаунт

`GET /api/me?access_token=…`
```json
{"data":{"isLogined":true,"id":129637,"name":"vpr","isPremium":true,"premiumUntil":"2030-04-26 23:41:55"}}
```
Премиум активен → скачивание доступно. Это **единственный** эндпоинт с данными пользователя.

### Списков просмотренного НЕТ

Проверены `me/watching`, `me/list`, `me/lists`, `me/favorites`, `me/history`, `me/anime`,
`me/settings` — **все возвращают ровно тот же объект, что `/api/me`** (роутер игнорирует хвост пути).
`userRates`, `watching`, `listItems`, `users/{id}` → `404`.

→ Синк статусов с Shikimori/AniList через Anime365 **невозможен**. Можно только вести пользователя
по ссылкам из `links[]`. Если понадобится — отдельная интеграция с API Shikimori/AniList (свой OAuth).

⚠️ **`embed` всегда возвращает ссылки на `smotret-anime.org`**, к какому бы зеркалу мы ни обратились.
Но те же пути работают на любом зеркале — проверено, `smotret-anime.online/translations/mp4/4505262`
отдаёт тот же файл с тем же `content-length`. → Нужен **rewrite хоста** ссылок скачивания на
выбранный `base_url`, иначе при блокировке `.org` каталог работает, а загрузки молча падают.

## Каталог

### ⚠️ `fields` обязателен

`GET /api/series` **по умолчанию отдаёт всё**: `episodes[]`, `descriptions[]`, `links[]`, `allTitles[]`.
Две записи = 38 КБ. Без `fields` полный каталог не выкачать.

### Объём

Полный скан `limit=1000&order=id&afterId=…` с урезанным `fields`:

| Метрика | Значение |
|---|---|
| Всего тайтлов | **29 231** |
| Запросов | 44 |
| Время | **32 секунды** |
| Размер JSON | 32,3 МБ (23,5 МБ без `allTitles`) |
| Максимальный `id` | 44255 (нумерация с дырами) |
| Онгоингов (`isAiring=1`) | 306 |

Распределение по типам:
`tv` 9255 · `movie` 5112 · `music` 4403 · `ona` 4341 · `ova` 2731 · `special` 1748 ·
`tv_special` 806 · `cm` 509 · `pv` 326

### Названия — критично для маппинга

```json
"titles": {"ru":"…","romaji":"…","ja":"…","en":"…","short":"…"}
```

| Поле | Заполнено |
|---|---|
| `romaji` | **29 169** из 29 231 |
| `en` | **13 412** (меньше половины!) |
| `allTitles[]` | у всех, в среднем **7.6** вариантов на тайтл |

→ Локальные папки названы по-английски, но `titles.en` есть лишь у 46% тайтлов.
**Матчить надо по `allTitles`**, а не по `titles.en`.

Также есть `titleLines[]`, `title` (склейка «ru / romaji»), `url` (страница на сайте).

### Внешние ID

| Поле | Заполнено | Годен как ключ |
|---|---|---|
| `myAnimeListId` | 28 566 | да |
| `anilistId` | 19 030 | да |
| `aniDbId` | 15 948 | **нет** — у всех трёх фильмов Heaven's Feel он один (10755) |
| `worldArtId`, `animeNewsNetworkId`, `fansubsId` | частично | не используем |
| `imdbId` | почти всегда 0 | нет |

Соответствий `tvdbid`/`tmdbid` (которые есть в `.nfo`) в каталоге **нет**.

### Жанры

Приходят прямо в списке: `genres: [{id, title, url}]`. Всего **74** жанра.
Топ: Комедия 7932, Детское 7085, Фэнтези 6185, Музыка 5554, Экшен 4995, Приключения 4623.
→ Фильтрацию делаем локально по кэшу. Серверный `chips=genre@=8,35;genre_op=and` тоже работает.

### Инкрементальное обновление

Поля `updatedDateTime` у series **нет** → изменения существующих тайтлов ловить нечем.
Стратегия: `afterId` для новых + `isAiring=1` для онгоингов (306 шт., секунды) + периодический
полный рескан (32 с).

### Поиск

`?query=` работает и по латинице, и по кириллице. Кириллицу **обязательно percent-encode**
(иначе ноль результатов). `query=Frieren` → 4 релевантных тайтла, `query=Зомбилэнд` → 4.

## Тайтл

`GET /api/series/{id}` добавляет к полям списка: `descriptions[]` (`{source, value, updatedDateTime}`),
`genres[]`, `episodes[]`, `links[]` (World Art, Шикимори, MAL, AniList, AniDB, Kage Project,
Wikipedia, Kinopoisk, Crunchyroll…).

### ⚠️ `numberOfEpisodes` — это план, а не факт

Re:Zero 4th Season: `numberOfEpisodes: 19`, а эпизодов типа `tv` в API реально **11**.
Ровно тот случай из ТЗ («вышло 22, всего 24»). Правило приложения:
```
total = max(numberOfEpisodes, кол-во tv-эпизодов в API, максимальный локальный номер)
```

## Эпизоды

```json
{"id":313150,"seriesId":30414,"episodeFull":"6 серия","episodeInt":"6","episodeTitle":"",
 "episodeType":"tv","firstUploadedDateTime":"…","isActive":1,"isFirstUploaded":1}
```

- `episodeInt` — **строка**, не число.
- ⚠️ `episodeType` бывает `preview` — **трейлеры лежат вперемешку с сериями** и у них свой
  `episodeInt: "1"`. У Frieren 29 «эпизодов» = 28 серий + трейлер. Фильтрация обязательна.
- Типы: `tv`, `movie`, `ova`, `ona`, `special`, `preview`, …

## Переводы

`GET /api/translations?seriesId=X&limit=1000&fields=…` — один запрос отдаёт все переводы тайтла
**вместе с вложенным объектом `episode`**. Очень удобно: страница тайтла = 1 запрос.

Поля: `id, seriesId, episodeId, type, typeKind, typeLang, qualityType, authorsList[],
authorsSummary, title, url, embedUrl, isActive, priority, addedDateTime, updatedDateTime`.
Плюс **`width`, `height`, `duration`** — они приходят и в списке, если запросить через `fields`.

### ⚠️ Пагинация переводов работает только с `feed=id`

Без `feed=id` выдача не отсортирована по id, и `afterId` даёт **пустую вторую страницу**, хотя
данные есть. Frieren: без `feed=id` → 1000 записей, `afterId=max` → 0. С `feed=id` → 1000 записей
(4384807…4877187), `afterId=4877187` → ещё 1000 (4877501…5652087). Всего у тайтла ~1966 переводов.

**Всегда `feed=id` + `afterId`.**

### Типы

`typeKind` ∈ `voice`, `sub`, `raw`, `voiceOth` · `typeLang` ∈ `ru`, `en`, `ja`, `er`(other)

Распределение у Frieren: `voiceRu` 317 · `raw`(ja) 252 · `voiceOther` 149 · `subEn` 107 ·
`subRu` 103 · `voiceEn` 49 · `subJa` 23. → `voiceOther`/`er` отбрасываем (нас интересуют ru/en/ja).

## Embed — главная недокументированная часть

`GET /api/translations/embed/{id}?access_token=…` (нужен премиум)

```json
{"data": {
  "embedUrl": "https://smotret-anime.org/translations/embed/4505262",
  "download": [{"height":1080,"url":".../translations/mp4/4505262?download=1&height=1080"},
               {"height":720,…},{"height":360,…}],
  "stream":   [{"height":1080,"urls":["https://ru-XXXXXX.<cdn>/s/<zone>/route/?m=…&r=…"]}, …],
  "subtitlesUrl": "/episodeTranslations/4505262.ass?willcache",
  "subtitlesVttUrl": "…"
}}
```

### 🔑 Признак «вшитые субтитры»

Для перевода с `typeKind == "sub"`: **`subtitlesUrl == null` ⇒ хардсаб**, иначе софтсаб.
Другого признака в API нет. Проверено: из 26 просмотренных sub-переводов 24 софтсаба и
2 хардсаба (Zombieland Saga id 19323, `subRu` от AniPlay, id 2229900 и 2229904).

⚠️ Узнать это можно **только через `embed`, то есть 1 запрос на перевод**. У тайтла бывает ~2000
переводов → массово не дёргаем. Лениво, при раскрытии группы, с кэшем в БД.

### Скачивание видео

`GET /translations/mp4/{id}?download=1&height=720&access_token=…`
→ `302` на CDN → `content-disposition: attachment; filename="[Anime365] Sousou no Frieren - 06 (t4505262).mp4"`

- **Без токена — 403.**
- Размеры: 1080p ≈ 229 МБ, 720p ≈ 92 МБ на 24-минутную серию.
- Формат имени `[Anime365] {romaji} - {NN} (t{translationId}).mp4` совпадает с тем, что уже лежит
  у пользователя в библиотеке.

### Скачивание субтитров

`GET /episodeTranslations/{id}.ass?willcache` — **токен не нужен**, `content-disposition`
отсутствует (имя формируем сами), формат `.ass`.

## Лестница качества — нелинейная

`translation.height`/`width` доступны в **дешёвом списочном запросе**, без `embed`.
Но набор ступеней в `embed.download` из исходной высоты **не выводится**:

| Источник | Ступени `download` | Замечание |
|---|---|---|
| 360 | `[360]` | |
| 396 | `[396]` | нестандартная ступень |
| 464 | `[480, 360]` | ступень **выше** источника |
| 480 | `[480, 360]` | |
| 526 | `[478]` | нестандартная и **ниже** источника |
| 528 | `[720, 360]` | апскейл |
| 540 | `[540, 360]` | |
| 720 | `[720, 360]` | |
| 1080 | `[1080, 720, 360]` | |
| **2160** | `[1080, 720, 360]` | **4K скачать нельзя, потолок 1080** |

Следствия:
- `height` из списка → **дешёвая оценка** максимума для сводки по тайтлу (без `embed`), в UI
  подписывается как оценка.
- Точные ступени → только `embed`, лениво + обязательно воркером перед скачиванием.
- «По умолчанию 1080» = фактически «максимум возможного».

## CDN

**Установлено:**
- `/diagnostic` требует **сессионную куку** сайта, `access_token` её не заменяет (302 на логин).
- `/api/me` полей о CDN не отдаёт; настройка CDN в аккаунте через API не видна.
- Параметры `server=28`, `cdn=1`, `sid=2`, `serverId=28` в ссылке скачивания **ни на что не влияют**.
- Цель `302` меняется от запроса к запросу: `ru-243434`, `ru-549959`, `ru-549959`, `ru-453324`
  (все `*.quantum-phantom-moon.ru`).
- **Но это не разные ноды.** `ru-549959.quantum-phantom-moon.ru/s/q1561620/…` — это
  `nginx/1.24.0 (Ubuntu)`, реверс-прокси перед зоной, а `moon-q1561620.b-cdn.net` — **та же зона
  BunnyCDN напрямую** (`server: BunnyCDN-DE1-864`, `cdn-pullzone: 207877`). Меняющийся префикс
  `ru-NNNNNN` — домен-фронтинг поверх одного бэкенда.
  → Идея «перезапрос = другая нода = быстрее» **не подтверждена**.

**Гипотеза, требующая проверки на сервере пользователя:**
- Тестовый файл `test100.bin` с машины разработки: **Bunny напрямую 22.8 МБ/с против 4.05 МБ/с
  через прокси** (в 5.6 раза).
- Подписанная ссылка на реальное видео прямым Bunny-хостом **принимается**:
  `https://ru-X.quantum-phantom-moon.ru/s/{zone}/route/?m=…&r=…`
  → `https://moon-{zone}.b-cdn.net/route/?m=…&r=…` → `206`.
  (Форма `/s/{zone}/route/` на Bunny даёт `404` — префикс зоны надо убирать.)
- ⚠️ Замер на **реальном видео не воспроизведён**: подписи `m=`/`r=` похожи на одноразовые —
  после первого обращения повторный GET отдаёт 0 байт и на прокси, и на Bunny. Плюс все замеры
  сделаны не из сети пользователя (Bunny определил страну как LV).

→ Реализация: **опциональный тоггл «пробовать прямой Bunny-хост»**, выключен по умолчанию,
автоматический откат на прокси при любой ошибке, встроенный замер скорости первого чанка в лог.

## Прочее

- Постеры (`posterUrl`, `posterUrlSmall`) отдаются **без токена**.
- Лимитов/банов при ~60 запросах в минуту не замечено, но ограничитель в клиенте всё равно делаем.
- Модификаторы `pretty=1` и `callback=` работают на любом эндпоинте.
- `/api/upload/endpoints` и `POST /api/translations/create` — это **загрузка на сайт**,
  к скачиванию отношения не имеют. В проекте не используются.
