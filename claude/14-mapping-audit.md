# Разбор маппинга на живой библиотеке (2026-08-04)

Пользователь сказал: «очень много папок смаппилось криво». Здесь — что именно
криво, почему, и что из этого следует для алгоритма. Правки по итогам ещё **не
сделаны**: файл заведён, чтобы чинить всё разом и по фактам, а не по одному
случаю.

## Как измерено

Сервер `bocchi@192.168.1.76`, **только чтение**: `ls`/`find`/`grep` по
библиотеке и снимок базы, скопированный внутрь одноразового контейнера
(`-v …/data:/data:ro` + tmpfs). Файлы пользователя не менялись.

Данные: развёрнутая версия — коммит `333a487`, то есть до правок этой сессии.

| корень | папок | привязано | без привязки, но с видео | видеофайлов |
|---|---|---|---|---|
| `/media/anime/library` | 317 | 247 | **0** | 2104 |
| `/media/anime_movies/library` | 55 | 54 | **0** | 52 |

⚠️ Важный вывод из последнего столбца: **непривязанных папок с содержимым
нет**. Проблема не в том, что чего-то не хватает, а в том, что привязки
**неверные** — а такая ошибка не видна, пока файл не уедет не в ту папку.

Ещё цифра: **33 тайтла держат больше одной папки**, у `Girls Band Cry` их

## Дефект 1. Подпапка наследует ID родителя, даже когда она не сезон

**20 папок.** Самый массовый случай.

`library_service.py` для любой дочерней папки берёт `.nfo` и название у
родителя:

```python
title_nfo = _nfo_of(parent) if parent is not None else _nfo_of(folder)
folder_name = parent.name if parent is not None else folder.name
```

А защита в `matcher.py` закрывает только один случай:

```python
if ctx.season_number not in (None, 1):   # ← None проскакивает
    return None
```

Jellyfin кладёт `season.nfo` **в каждую** подпапку, включая служебные, и у
служебных в нём нет `<seasonnumber>`. Поэтому `season_number is None`, ID
родителя принимается, уверенность 100%.

Что так смаппилось (все — на тайтл родителя):

| папка | видео | что это на самом деле |
|---|---|---|
| `Girls Band Cry/subtitles` | 0 | папка с субтитрами |
| `Girls Band Cry/ScreenShot` | 0 | скриншоты |
| `Girls Band Cry/subs2srs output` | 0 | выгрузка для Anki |
| `Girls Band Cry/EXTRA` | **39** | BD-сканы и бонусный диск |
| `Girls Band Cry/Movie 1 …`, `Movie 2 …` | 1, 2 | **два отдельных фильма** |
| `Fate+Zero/NC`, `/Bonus` | 4, 3 | безкредитные OP/ED и бонусы |
| `Bocchi the Rock!/LIVE` | 1 | концерт |
| `Bocchi the Rock!/Gekijou Soushuuhen … Movie` | 2 | **фильм-компиляция** |
| `Bang Dream!/Movies and OVAs` | 8 | фильмы и OVA |
| `Toradora!/Toradora 10th Anniversary 10bit` | 29 | другой релиз того же сезона |

Плюс один случай с номером сезона, который всё равно проскочил:
`Yuru Camp/[Ohys-Raws] Yuru Camp Season 2 …`.

**Что делать.** Различать «свой `.nfo`» и «унаследованный» и принимать ID
родителя только при `<seasonnumber> == 1`. Нет номера сезона — это не сезон, а
фильм, спешл или служебная папка, и родительский ID к ней отношения не имеет.
Название тоже наследовать нельзя: у `Movie 1 - Youth Rhapsody` есть шанс
попасть в настоящий фильм по своему имени, а под именем родителя — ноль шансов.

## Дефект 2. Битый `.nfo` у папки-контейнера протекает во всё поддерево

**7 папок на один неверный тайтл.**

`Evangelion/tvshow.nfo` описывает не сериал, а показ к 30-летию 2026 года:

```
<title>Evangelion: Housou 30 Shuunen Kinen Tokubetsu Kougyou
<anilistid>204270      ← показ 2026 года
<shikimoriid>30        ← а это настоящий NGE 1995
```

Jellyfin сматчил папку-франшизу на этот показ. Дальше по наследству:
`Evangelion/Season 1` — **26 серий оригинального сериала** — сел на показ, и
все четыре папки фильмов тоже.

Два отдельных следствия:

* **в одном файле два ID, указывающие на разные тайтлы**, и `anilistid`
  побеждает молча. Противоречие — это сигнал «данные ненадёжны», а не повод
  выбрать первый попавшийся;
* **никто не проверил правдоподобие**: у папки 26 видеофайлов, у кандидата
  один эпизод. Такое совпадение обязано отвергаться.

* **неразрешимая ничья — не повод молча выбрать первого.** Такую привязку надо
  ставить с пометкой «ждёт подтверждения», она для этого и заведена;
* совпадение обоих ID (170 из 236) — наоборот, **усиливает** уверенность, и
  такие случаи можно принимать без строковой проверки.

## Дефект 4. Сезоны сериала слипаются в один тайтл

`Monogatari` разложен на шесть сезонов; `Season 4` сел на `Bakemonogatari`
(первый сезон) по `exact_title` 99, `Specials` — туда же по `premiered`.
`Honzuki no Gekokujou S1+S2+S3 x265 10bit` — семь папок на один тайтл, из них
`Season 1` (39 видео) село на **OVA** с одним эпизодом.

Причина та же, что у дефекта 1, плюс: когда каскад C не находит сезон по
кварталу премьеры, управление уходит в строковый каскад B, а тот сравнивает
название **родителя** и находит первый сезон. Номер сезона при этом не
учитывается вовсе.

**Что делать.** Если у папки есть `<seasonnumber> > 1`, результат каскада B,
указывающий на тайтл первого сезона, принимать нельзя — это заведомо не он.

## Откуда вообще берутся эти `.nfo` (вводные от пользователя, 2026-08-04)

Библиотека наполнялась через **Sonarr/Radarr + Prowlarr**, а метаданные пишет
Jellyfin плагинами в таком порядке:

* сериалы: **AniList → TheMovieDb → Shikimori → Kitsu → AniDB**
* фильмы: **AniList → TheMovieDb → Shikimori → AniDB**

Это объясняет почти всё, что мы намерили, и меняет постановку задачи.

### 1. Имена папок и `.nfo` — из разных систем координат

**Jellyfin папки не переименовывает** — он только пишет метаданные.
Переименовывают Sonarr/Radarr, а они живут в **TVDB** (сериалы) и **TMDB**
(фильмы). Значит:

* имя папки и разбиение на `Season N` — это **модель TVDB**, где франшиза
  обычно один сериал с несколькими сезонами;
* `.nfo` — это модель **AniList/Shikimori**, где каждый сезон отдельный тайтл;
* Anime365 устроен как AniList: сезон = отдельный `series_id`.

Отсюда дефект 4 (слипание сезонов) — не случайность, а **системное расхождение
двух моделей**. `Monogatari/Season 1…6` — это шесть разных тайтлов Anime365 и
один сериал TVDB. Алгоритм обязан переводить между моделями явно, а не
надеяться, что название сойдётся.

### 2. Почему два ID в одном файле расходятся

AniList стоит **первым**, поэтому `<title>`, `<originaltitle>` и `<anilistid>`
приходят от одного плагина и **согласованы между собой**. `<shikimoriid>` пишет
другой плагин, который матчил **независимо**, — и промахивается сам по себе.

Это ровно та картина, что в замере: 66 расхождений из 236. И это меняет
формулировку проверки:

* по `anilistid` найденный тайтл сверять с названием **из того же `.nfo`** —
  проверка честная, источник у них общий;
* `shikimoriid` без подтверждения не принимать никогда (это уже так);
* совпали оба — уверенность выше, чем у каждого по отдельности.

### 3. `tvdbid` — недоиспользованный ключ

В `season.nfo` есть `<tvdbid>` **сезона** (например 2060398 у Girls Band Cry
Season 1), в `tvshow.nfo` — `<tvdbid>` сериала. В Anime365 их нет, но они дают
то, чего нет больше ни у чего: **стабильный идентификатор папки**, переживающий
переименование Sonarr'ом.

Что с этим делать:

* ручные привязки и подтверждения хранить с оглядкой на `tvdbid` + номер
  сезона, а не только на путь: arr-стек будет поднят заново и папки
  переименует;
* пара «tvdbid сериала + seasonnumber» — естественный ключ для перевода из
  модели TVDB в модель Anime365, и его можно накапливать по мере подтверждений.

### 4. Jellyfin API — проверено, чуда не будет

Ключ в развёрнутом приложении **не задан** (`A365_JELLYFIN_API_KEY` пуст), API
снаружи не отвечает. Но ответ виден и по `.nfo`: на уровне **сезона** Jellyfin
знает только `tvdbid`, никаких AniList-ID там нет. То есть посезонных
AniList-идентификаторов от него ждать не стоит.

Что API всё же может дать, когда ключ появится: `ProviderIds` у Series/Movie
целиком (то же, что в `.nfo`, но без чтения диска) и — главное — ответ на
вопрос «что Jellyfin считает одним тайтлом», то есть готовую группировку папок.
Проверить стоит, но закладываться на это в алгоритме нельзя: интеграция
выключена по умолчанию, а маппинг обязан работать без неё.

### 5. Следствие для порядка правок

Пункты 1–4 прежнего плана остаются, но добавляется нулевой: **алгоритм должен
явно знать, что имя папки — из TVDB, а `.nfo` — из AniList**, и не пытаться
свести их строковым сравнением. Сезон разводится по `<seasonnumber>` +
`<premiered>` (уже есть) и по паре «базовое название + номер», а `tvdbid`
становится ключом устойчивости к переименованиям.

поле бесполезно. Хорошо, что проверили до того, как на нём что-то построили.

### Что Jellyfin всё же даёт

Проверено по публичному адресу с ключом из `.env.app`:

* **у `Series` и `Movie` — по 4–6 идентификаторов** (AniList, Shikimori, Kitsu,
  AniDB, Imdb, Tmdb) против двух, доезжающих до нас в `.nfo`;
* **у `Season` — почти ничего**: пусто или один `Tvdb`. Посезонных AniList-ID
  не существует, и ждать их неоткуда;
* **происхождения полей нет**: какой плагин что дал — не записано нигде;
* `DateLastRefreshed` в ответе отсутствует.

Главное следствие — **противоречие видно внутри самой записи Jellyfin**:

```
Evangelion  → AniList 204270 (показ 2026) | Imdb tt0112159 + Kitsu 21 → NGE 1995
Your Name.  → AniList 97962 (реклама воды) | Imdb tt5311514 + Shikimori 32281 → «Твоё имя»
```

То есть ошибся сам AniList-плагин Jellyfin, а `.nfo` лишь честно её отражает.
Anime365 в этих двух случаях ни при чём — прежняя формулировка была неточной.

Отсюда усиление арбитража: **голосование по нескольким ID**. Anime365 умеет
сопоставлять три из них (AniList, MAL/Shikimori, AniDB), и большинство голосов
разрешает оба случая. Но это усилитель, а не фундамент: интеграция выключаема и
ходит по сети, поэтому основной путь остаётся прежним — сверка по названию,
году, типу и числу файлов.

## Граница ответственности (решение пользователя, 2026-08-05)

Пользователь поправил «Твоё имя» вручную в Jellyfin — там и название было про
минеральную воду, а не только идентификатор. И сформулировал принцип, с которым
я согласен:

> по хорошему это ошибка на стороне Jellyfin, и такое должно правиться руками,
> а то, что оно вследствие у нас криво замапилось бы, — скорее не наша проблема

**Что из этого следует для алгоритма.** Чинить чужую идентификацию мы не
пытаемся: любая эвристика, которая «знает лучше» разметки, неизбежно начнёт
ломать верные случаи — вроде `Genshiken` с другой романизацией. Источник правды
живёт в Jellyfin, и правки нужно вносить там.

**Но одно всё же наше.** Есть разница между двумя исходами:

* «разметка говорит про воду → мы привязали туда» — честный мусор на входе,
  мусор на выходе, вопросов нет;
* «мы привязали туда с уверенностью 100% и ничем не пометили» — а это уже наша
  ошибка: такую папку не найти, пока файлы не уедут не туда.

Поэтому проверка осталась, но её цель переформулирована: **не выбрать правильный
тайтл вместо Jellyfin, а не делать вид, что мы уверены**. Если мы отвергли
идентификатор из разметки и взяли другого кандидата, привязка помечается «ждёт
подтверждения» — это приглашение сходить и поправить в Jellyfin, а не наша
попытка переголосовать источник.

Практическое следствие для будущих правок: **молчаливое переголосование разметки
запрещено**. Любое расхождение с `.nfo` обязано быть видно в интерфейсе.

## Прогон новым алгоритмом на живой библиотеке (2026-08-05)

Первый честный прогон: образ пересобран, скан библиотеки запущен, 384 папки,
311 привязок. Разбор того, что осталось кривым.

### ⚠️ Главная находка: `.nfo` описывает **другое аниме**

Это оказалось причиной «большинство фильмов вообще не впопад». Содержимое
файлов, снятое с сервера:

| папка | `<title>` в её `.nfo` |
|---|---|
| `A Silent Voice - The Movie` | `Meitantei Conan Magic File 2: Kudou Shinichi…` |
| `Look Back` | `Kekkai Sensen & Beyond: Zapp Renfro Ingaouhouchuu!!` |
| `Cencoroll Connect` | `Connected…`, `anilist_id 3087` |

Матчер приводил к тому, что написано, и совпадение выходило **точным** (99%).
То есть Конан не выдуман алгоритмом — он прописан в `tvshow.nfo` этой папки.

**Решение — сравнивать имя папки с `title` из `.nfo`.** Знать, какое аниме
правильное, мы не можем; заметить противоречие двух источников в одной папке —
можем.

⚠️ **Порогом по строкам это не решается, и это измерено:**

```
«A Silent Voice - The Movie» ↔ «Meitantei Conan Magic File 2»  →  42,3   чужое
«Yuru Camp»                  ↔ «Laid-Back Camp»                →  43,5   то же самое
```

Один балл разницы при противоположном смысле. Поэтому сравниваются **тайтлы, к
которым строки приводят**: «Yuru Camp» и «Laid-Back Camp» находят один тайтл
каталога, «A Silent Voice» и «Meitantei Conan» — разные. Порог выброшен как
бесполезный ([D-86](09-decisions.md)).

### Что осталось кривым после прогона

| случай | что видно | причина |
|---|---|---|
| `Toradora!` + `Toradora!/Season 1` | обе папки на одном тайтле | правило «контейнер уступает подпапке» не срабатывает: в корне лежит 1 видео |
| `Classroom of the Elite` | 17 файлов 4-го сезона → 1-й сезон (12 серий) | нет признака «файлов больше, чем серий у кандидата» |
| `Honzuki…/Season 1` | 39 серий на тайтл с 14 | Sonarr слил три сезона в одну папку; развести можно только по номерам серий |
| спешлы K-On!, YuruYuri, Bocchi, Toradora | садятся на первый сезон | надо проверить, есть ли в каталоге отдельные тайтлы под эти спешлы |
| `Bang Dream!/Movies and OVAs` | 8 фильмов → один тайтл | в одной папке несколько разных фильмов |
| `Girls Band Cry Movie 1/2` | обе части → «Girls Band Cry Movie» (総集編) | в каталоге, похоже, только компиляция |
| фильм Резе | японские субтитры не видны | файлы в базе есть (`video=1, subtitle=3`), но не привязаны к серии: у фильма нет номера |
| `Girls Band Cry/EXTRA` и прочие служебные | по-прежнему на тайтле родителя | **проверить после следующего перескана** — правка про наследование выехала позже |

### Ловушки развёртывания, на которые наступили

* **два разных процесса называются «сканирование»** — синхронизация каталога с
  сайта и обход библиотеки на диске. Пользователь увидел «сканирование
  завершено» (это был каталог) и ждал новых привязок. Надо развести названия;
* **скан, прерванный перезапуском, оставался `running` навсегда** — индикатор
  показывал вечное «идёт сканирование». Починено: при старте такие записи
  закрываются;
* **привязки не пересчитываются сами** — после обновления образа нужен скан
  библиотеки кнопкой, иначе на экране остаются результаты прежнего алгоритма.
  Дважды приняли старые данные за новые.
