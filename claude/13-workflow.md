## Правила работы

* **Коммитить и пушить регулярно**, а не в конце. Пользователь про это
  напоминал; целый день несохранённой работы — плохо.
* **Перед коммитом проверить, что нет секретов.** Токен Anime365 лежит в `.env`
  (по просьбе пользователя), ключ Jellyfin передаётся переменной окружения.
  `.env`, `config/`, `data/`, `temp/` — в `.gitignore`, это проверено
  `git check-ignore`. Ни то ни другое не должно попадать ни в код, ни в
  документацию, ни в примеры команд.
  Проверка перед коммитом: `git diff --cached | grep -oE "\b[a-f0-9]{32,}\b"`
  (пусто = чисто).
* **Не гадать, а измерять.** Почти каждая ошибка в этом проекте была там, где
  что-то казалось очевидным: что `st_dev` достаточно, что логотипы всегда
  `.png`, что `follow_redirects` не нужен. Проверка занимает минуты.
* **Правки документации — вместе с кодом**, в том же коммите. Разъехавшаяся
  документация обнаруживается через недели.
* **Оглавления пересчитывает хук.** Включается один раз на машину:
  `git config core.hooksPath scripts/hooks`. Он запускает
  `scripts/update_docs_toc.py` перед коммитом и доносит в него **только те**
  `.md`, которые в коммите и так были. Без хука остаётся ручной запуск, а
  забытый ловит `backend/tests/test_docs_toc.py` — но уже после коммита.
* **После любой правки `.md` — `python scripts/update_docs_toc.py`.** У каждого
  документа сверху таблица «строка → раздел», и любая вставленная строка сдвигает
  номера ниже неё. Ломается это молча: оглавление выглядит правдоподобно и уводит
  не туда. Номера руками не правим — их считает скрипт, а сторожит
  `tests/test_docs_toc.py`.
* **Переименовали заголовок — проверьте ссылки на него из других файлов:**
  `grep -rn "старый-якорь" --include="*.md" .`. Внутри своего файла битую ссылку
  поймает тест, чужую — нет.
* **Читать документацию тоже надо через оглавление**: сначала верх файла (сводка
  «зачем он» плюс таблица разделов), потом нужный кусок по номеру строки. Правило
  для ассистента записано в [CLAUDE.md](../CLAUDE.md).

## Что где лежит для проверок

| Что | Где | Зачем |
|---|---|---|
| Настоящие файлы аниме | `temp/YuruYuri - Happy Go Lily/`, `temp/Zombie Land Saga/` | Проверять сканер, разбор имён, `.nfo` и ffmpeg на реальных данных. Есть HEVC + Opus — на нём проверялось, что ffmpeg жив после зачистки образа |
| Списки файлов библиотеки | `temp/tree.txt`, `temp/tree_movies.txt` | Прогон парсера имён по реальной библиотеке пользователя |
| Отчёты сканера уязвимостей | `temp/results_scan.txt`, `temp/results_recommendations.txt` | Обновлять после правок Dockerfile |

`temp/` в `.gitignore` — файлы туда кладёт пользователь, в репозиторий они не
уезжают.

## Команды

Сборка и запуск для проверки:

```
docker build -t anime365-downloader:0.1.0 .
docker run -d --name a365-test -p 8099:8080 --env-file .env \
  -v "<репозиторий>/temp:/media/animeseries:ro" \
  -v "<scratchpad>/mnttest:/media/rw" \
  -v "<scratchpad>/a365data:/data" \
  -e A365_SERIES_ROOT=/media/animeseries -e A365_MOVIES_ROOT=/media/rw/movies \
  -e A365_AUDIO_ROOT=/media/rw/audio -e A365_DOWNLOAD_TMP=/media/rw/.a365-tmp \
  -e A365_DB_PATH=/data/app.sqlite3 anime365-downloader:0.1.0
```

Три вещи здесь важны, и все три — по просьбе пользователя:

* **`temp/` монтируется корнем сериалов, только на чтение.** Там настоящее
  аниме с `.nfo` и субтитрами: сканер, разбор имён и маппинг надо проверять на
  нём, а не на выдуманных папках. `ro` — чтобы ничего нельзя было испортить.
  На полном каталоге маппинг сходится: 6 папок из 6;
* **база лежит в scratchpad, а не в контейнере.** Иначе каталог сносится при
  каждой пересборке и синхронизировать приходится заново. Полный каталог —
  29 214 тайтлов, около минуты. **Каталог обновлять, а не сносить:**
  `POST /api/catalog/sync {"mode":"incremental"}`;
* **`--env-file .env`** даёт токен Anime365.

Тесты **внутри образа** — так проверяется тот стек, что поедет на сервер:

```
docker run --rm --entrypoint sh -v "$PWD:/repo:ro" -u root anime365-downloader:0.1.0 \
  -c "pip install -q pytest pytest-asyncio; cd /repo/backend && PYTHONPATH=/repo/backend python -m pytest tests -q"
```

Наполнить каталог для проверки: `POST /api/catalog/sync {"mode":"airing"}` даёт
306 онгоингов за секунды; `search-online?query=…` подтягивает конкретный тайтл.

## Грабли окружения

* **Git Bash коверкает пути** в `docker run`/`exec`: `/data/app.sqlite3`
  превращается в `C:/Program Files/Git/data/...`. Лечится префиксом
  `MSYS_NO_PATHCONV=1` перед командой.
* **`docker restart` не подхватывает новый образ.** Нужно `docker rm -f` и
  `docker run` заново. На этом дважды разглядывался старый бандл.
* **Браузер кэширует `index.html`.** После пересборки образа страница может
  выполнять старый бандл — и это выглядит как «баг вернулся»: пропавшие элементы,
  чужие ошибки React в консоли. На это уже уходил час впустую.
  Проверять так:

  ```js
  fetch('/?x=' + Date.now()).then(r => r.text()).then(h => console.log(
    'сервер отдаёт:', h.match(/assets\/index-[^"]+\.js/)[0],
    'браузер выполняет:', [...document.scripts].map(s => s.src)))
  ```

  Не совпало — открыть `/` с новым query, обычной перезагрузки может не хватить.
* **Буфер `read_console_messages` не чистится** ни `console.clear()`, ни
  переходом. Старые записи выглядят как свежие; отличать их надо по имени бандла
  в стеке. Надёжнее подменить `console.error` своим сборщиком в `window`.
* **Замеры скорости с Windows врут.** Через проброс портов Docker Desktop любой
  ответ, включая статический файл, стоит около 220 мс. Мерить — изнутри
  контейнера.
* **Локальная БД разработчика — тестовая**, каталога в ней нет. Реальные данные
  только в контейнере.
* **Временная БД тестов переживает прогоны** (`/tmp/a365-tests.sqlite3`). Из-за
  этого тесты, зависящие от порядка, на своей машине проходят, а на чистой —
  нет. Проверять на свежем контейнере.
* **Перетаскивание синтетическими событиями не проверить.** dnd-kit опирается
  на захват указателя (`setPointerCapture`), а его у выдуманных `PointerEvent`
  нет; клавиатурный путь тоже не отрабатывает. Проверять — руками в браузере.
* **Кириллица в теле `curl` через Git Bash искажается.** Пароль доезжал до
  контейнера верно, а запрос уходил с другими байтами — выглядело как «вход не
  работает». Проверять учётные данные на латинице.
* **Вывод python в Git Bash падает на кириллице.** `UnicodeEncodeError: charmap`
  — нужен `export PYTHONIOENCODING=utf-8` перед разбором JSON-ответов.
* **`subprocess` с `encoding="utf-8"` не читает stderr дочернего процесса на
  Windows.** Тот пишет в кодировке консоли (cp1251), поток-читатель падает с
  `UnicodeDecodeError`, а `result.stderr` молча становится `None` — тест
  разваливается не там, где смотрит. Нужен `errors="replace"`.
* **`node`/`npm` не на PATH** в Bash-инструменте: нужен
  `export PATH="/c/Program Files/nodejs:$PATH"`.
* **Python в Bash — виндовый.** `subprocess.run(['find', ...])` вызовет
  `find.exe` — совсем другую утилиту, и проверка тихо вернёт пустой результат.
  Использовать `pathlib`.
* **Ссылка на решение внутри `09-decisions.md` — только полным слагом.**
  `[D-140](#d-140)` ведёт в никуда: якорь собирается из **всего** заголовка
  («d-140-пустая-подпапка-не-мапится…»). Короткую форму ловит
  `test_anchors_lead_somewhere`, но уже после правки. Проще писать `D-140`
  текстом — так сделано у большинства перекрёстных ссылок.
* **Heredoc в Bash коверкает обратные слэши.** Многострочный Python со
  спецсимволами лучше писать инструментом Write, а не через `<< 'PY'`.
* **Windows не заводит папки с `:` в имени.** В библиотеке есть
  `Gate: Jieitai Kanochi nite, Kaku Tatakaeri`, поэтому воспроизводить раскладку
  надо **внутри контейнера**, а не в scratchpad.
* **Воссоздавая библиотеку для проверок, имена файлов брать настоящие.**
  Спешлы опознаются по имени файла: назвав их по имени подпапки
  (`Specials S00E01.mkv`), получите ложный вывод «спешлы не работают».
* **Пересоздание контейнера из образа откатывает подложенный код.** После
  `docker rm -f` + `docker run` правки, скопированные через `docker cp`,
  исчезают — и прогон идёт по старому коду.

| Зависимости | `tests/test_dockerfile_deps.py` — списки в `pyproject` и `Dockerfile` продублированы намеренно, ради кэша слоёв |
| Настройку в реестре | `tests/test_compose_env.py` и `tests/test_settings_i18n_sync.py` — переменная должна попасть в compose, а подписи в `ru.ts` совпадать дословно |
| Dockerfile | Пересобрать и **прогнать скан**; проверить, что зачистка сработала (там стоят `test !`, но лишним не будет) |
| Фронтенд | `tsc --noEmit`, `npm run lint`, `npm run build`. Линтер ловит хуки после раннего `return` — компилятор такое пропускает, а страница падает в браузере |
| Индекс или запрос каталога | `tests/test_catalog_indexes.py` — **каждое** обращение к `series` в плане обязано быть покрывающим, и тест перебирает 60 сочетаний фильтров с сортировками. Одного `COVERING` где-то в плане мало: так пропустили фильтр по сезону с сортировкой по оценке за 4,7 с. | Сортировку в каталоге | Ещё и `SORT_INDEX` в `api/catalog.py`: индекс называется явно, и без записи в таблице запрос просто упадёт |
| Транзакции | `tests/test_db_locking.py` и `tests/test_transaction_hygiene.py` — границы транзакций и запрет `await` внутри них |
| Любой `.md` | `python scripts/update_docs_toc.py`, дальше `tests/test_docs_toc.py`. Номера строк в оглавлениях сдвигает **любая** вставленная строка, не только новый заголовок |
| Матчер или сканер | `claude/16-mapping-pipeline.md` — документ описывает **порядок признаков** и список вето, и обновлять его надо тем же коммитом |
