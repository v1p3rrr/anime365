## Что такое fuzzy-матчинг (термин из плана)

Сравнение строк «на похожесть» вместо «равно / не равно». Алгоритм считает, сколько правок
(вставок, удалений, замен символов) нужно, чтобы превратить одну строку в другую, и выдаёт оценку
0–100. Используем `rapidfuzz.token_set_ratio` — он дополнительно бьёт строку на слова и игнорирует
их порядок и повторы, поэтому устойчив к перестановкам и лишним словам.

Зачем он здесь:

| Папка | Каталог | Точное сравнение | Fuzzy |
|---|---|---|---|
| `YuruYuri - Happy Go Lily` | `YuruYuri: Happy Go Lily` | ✗ (одно двоеточие) | ~97 |
| `Wotakoi - Love Is Hard for Otaku` | `Wotaku ni Koi wa Muzukashii` | ✗ | низкий → нужен другой путь |
| `Yuru Camp` | `Yuru Camp△` | ✗ | ~95 |

Порог — компромисс: слишком низкий начнёт склеивать разные сезоны и похожие названия, слишком
высокий заставит всё мапить руками. Поэтому порог вынесен в настройки, а всё, что попало в серую
зону, идёт **не в авто-маппинг, а в «предложения»** на подтверждение.

## Входные данные

### Из файловой системы
- имя папки тайтла (`YuruYuri - Happy Go Lily`, `Fate+stay night - Heaven's Feel I. Presage Flower`)
- имена сезонных подпапок (`Season 1`, `Specials`) — либо их отсутствие
- имена файлов
- размер и mtime (для инкрементального скана)

### Из `.nfo` (пишет Jellyfin, лежат рядом с файлами)

| Файл | Полезные поля |
|---|---|
| `tvshow.nfo` | `<title>`, `<originaltitle>`, `<year>`, `<premiered>`, `<anilistid>`, `<shikimoriid>`, `<tvdbid>`, `<tmdbid>`, `<imdb_id>`, `<kitsuid>` |
| `season.nfo` | `<title>`, `<year>`, **`<premiered>`**, `<seasonnumber>`, `<tvdbid>`, `<plot>` |
| эпизодный `.nfo` | `<showtitle>`, **`<season>`**, **`<episode>`**, `<title>`, `<aired>`, `<fileinfo><streamdetails>` |
| `movie.nfo` | `<title>`, `<originaltitle>`, `<year>`, `<premiered>`, `<anilistid>`, `<shikimoriid>`, `<tmdbid>`, `<imdbid>`, `<streamdetails>` |

### Из каталога Anime365
`allTitles[]` (в среднем 7.6 вариантов), `titles.{ru,romaji,ja,en,short}`, `year`, `season`
(«Лето 2012»), `type`, `numberOfEpisodes`, `myAnimeListId`, `anilistId`.

## ⚠️ Главный принцип

**Строковый матчинг — основной механизм, ID — только ускоритель.**

Причины (проверено):
- `anilistId` заполнен у **19 030** тайтлов из 29 231, `myAnimeListId` — у 28 566;
- в `.nfo` соответствующих тегов может не быть вовсе (зависит от плагина Jellyfin);
- `<shikimoriid>` бывает **просто неверным**.

Поэтому каскад B обязан вытягивать папку самостоятельно, без единого ID.

## Каскад A — быстрые точные совпадения

Применяются только если данные есть. Результат помечается `confidence = exact`.

| Шаг | Правило | Надёжность |
|---|---|---|
| A1 | `<anilistid>` → `anilistId` каталога | высокая, совпал везде на тестах |
| A2 | `<shikimoriid>` → `myAnimeListId` | **только с подтверждением по названию** |
| A3 | `<originaltitle>` → `titles.ja` (точное совпадение японского) | высокая |

### Проверка на реальных данных

| Тайтл | `.nfo` | Каталог | Итог |
|---|---|---|---|
| Fate HF I | `anilistid` 20791, `shikimoriid` 25537 | series 7427: `anilistId` 20791, `myAnimeListId` 25537 | оба ✅ |
| YuruYuri | `anilistid` 10495, `shikimoriid` 11589 | series 260: `anilistId` 10495, `myAnimeListId` 10495 | anilist ✅, shikimori ❌ |

`<shikimoriid>` 11589 у YuruYuri указывает на совершенно другое аниме («Pu-Neko»). Именно поэтому
A2 требует подтверждения.

### `aniDbId` как ключ не годится
У всех трёх фильмов Heaven's Feel он одинаковый — **10755**. Использовать нельзя.

### `tvdbid` / `tmdbid` бесполезны
В каталоге Anime365 соответствий нет (`imdbId` почти всегда 0).

## Каскад B — строковый матчинг (работает всегда)

### B0. Собрать кандидатные строки
Имя папки, `<title>` и `<originaltitle>` из `tvshow.nfo`/`movie.nfo`, `<showtitle>` из эпизодных `.nfo`.

Замечание: `<title>` в `.nfo` часто **лучше** имени папки. У YuruYuri папка называется
`YuruYuri - Happy Go Lily`, а в `tvshow.nfo` стоит `Yuru Yuri` — это ровно `titles.romaji` каталога.

⚠️ **Сначала выбирается сам файл.** Рядом их бывает несколько: в корне фильмов у 42 папок из 58
лежат и `movie.nfo`, и `tvshow.nfo`, и второй остался с тех пор, когда эти папки сканировались
как сериальная библиотека — у 35 папок он называет вообще другое аниме. Приоритет задан по корню
(`NFO_PRIORITY`): в фильмах `movie` > `season` > `tvshow`, в сериалах наоборот
([D-87](09-decisions.md)).

⚠️ И даже правильно выбранный `.nfo` может описывать другой тайтл, чем папка — тогда берётся
только имя папки ([D-86](09-decisions.md)).

### B1. Нормализация

| Шаг | Пример |
|---|---|
| lowercase | |
| `+` → `/` | `Fate+stay night` → `fate/stay night` (в имени файла `/` запрещён) |
| развернуть юникодные римские цифры U+2160–U+217F | `Ⅰ.presage flower` → `i.presage flower` |
| NFKC-нормализация + снятие диакритики | |
| удалить `[…]` и `(…)` | `(AT-X 1920x1080 x265 AAC)`, `[Ohys-Raws]` |
| удалить технический хвост | `Bluray-1080p`, `HDTV-1080p`, `WEBDL-720p`, `x265`, `AAC` |
| `☆ ★ ・ △ ♪` → пробел | `Yuru Yuri San☆Hai!` → `yuru yuri san hai` |
| `’` → `'`, убрать остальную пунктуацию | |
| схлопнуть пробелы | |
| **выделить номер сезона в отдельный признак** | `Season 2`, `S2`, `2nd Season`, `II`, `♪♪` |

Важно: номер сезона идёт **не в строку названия**, а в отдельное поле — иначе `Yuru Yuri♪♪`
и `Yuru Yuri` будут неразличимы после чистки символов.

### B2. Точное совпадение по `allTitles`
Строим индекс: нормализованный вариант → `series_id` (≈222 тыс. ключей на 29 231 тайтл).
Один кандидат → авто-маппинг. Здесь окупается то, что `allTitles` есть у всех, а `titles.en` — нет.

### B3. Fuzzy по кандидатам из FTS5

| Оценка | Действие |
|---|---|
| ≥ 88 | авто-маппинг |
| 75–88 | «предложение», требует подтверждения в UI |
| < 75 | в список нераспознанных |

### B4. Разрешение неоднозначности
При нескольких кандидатах, по порядку:
1. **год / квартал** — `<year>` и `<premiered>` из `.nfo` против `year` и `season` каталога;
2. **тип** — папка в корне фильмов → `type = movie`; в корне сериалов → `tv/ona/ova/special`;
3. **число серий** — сколько локальных видеофайлов против `numberOfEpisodes`.

## Каскад S — папка спешлов

Срабатывает, когда у папки нулевой номер сезона (`Specials`, `Extras`, `OVA`,
либо `<seasonnumber>0</seasonnumber>`). В Anime365 спешлы — **самостоятельные
вхождения**: у K-On! их четыре, у Toradora! три, у Yuru Yuri пять с лишним.

1. **Идентификаторы родителя не предлагаются.** `anilistid` из `tvshow.nfo`
   указывает на сериал; спешлу он чужой.
2. **Кандидаты — по префиксу названия франшизы.** Не нечётким сравнением:
   спешл называется длиннее сериала («Toradora!» против «Toradora!: SOS!
   Kuishinbou Banbanzai»), и порог похожести его не берёт.
3. **Отсев по типу:** `special`, `tv_special`, `ova`, `ona`.
4. **Выбор — по имени файла.** Сама папка называется «Specials», а вот файл
   внутри назван конкретным спешлом. Сравнение `token_set_ratio` со всеми
   вариантами названия кандидата; побеждает только единоличный лидер.
5. Если имя файла не развело кандидатов — привязка ставится с пометкой
   «требует подтверждения» и уверенностью 70.

Решения: [D-96](09-decisions.md), [D-97](09-decisions.md).

⚠️ **Граница.** Кандидатов набирает префикс, поэтому спиноф, названный иначе
франшизы, по папке `Specials` не найдётся — `Mini Yuri` у Yuru Yuri именно
такой. Имя файла помогает выбрать среди найденных, но само кандидатов не ищет.

## Каскад C — сезоны

В Anime365 **каждый сезон это отдельный `series_id`**: Yuru Yuri → Yuru Yuri♪♪ → Yuru Yuri San☆Hai!,
Zombieland Saga → Zombieland Saga Revenge. Поэтому папка `Show/Season 2` мапится на **другой**
`series_id`, чем `Show`. `<anilistid>` из `tvshow.nfo` указывает только на первый сезон.

### C1. Основное правило — `<premiered>` из `season.nfo` → `season` каталога

Проверено на YuruYuri, где в каталоге **8** похожих тайтлов:

| Папка | `<premiered>` | Anime365 | |
|---|---|---|---|
| Season 1 | 2011-07-05 | id 260 `Yuru Yuri`, **Лето 2011**, 12 эп | ✅ |
| Season 2 | 2012-07-02 | id 3499 `Yuru Yuri♪♪`, **Лето 2012**, 12 эп | ✅ |
| Season 3 | 2015-10-05 | id 13077 `Yuru Yuri San☆Hai!`, **Осень 2015**, 12 эп | ✅ |
| Specials | 2011-11-16 | id 9888 `special`, **Осень 2011**, 1 эп | ✅ |

Все 8 кандидатов каталога:
```
260    tv          2011  Лето 2011    12 эп  Yuru Yuri
9888   special     2011  Осень 2011    1 эп  Yuru Yuri: Doushite, Tomaranai, …, Paradox, Eternal
3499   tv          2012  Лето 2012    12 эп  Yuru Yuri♪♪
8613   ova         2015  Зима 2015     1 эп  Yuru Yuri Nachuyachumi!
12880  tv_special  2015  Лето 2015     2 эп  Yuru Yuri Nachuyachumi!+
13077  tv          2015  Осень 2015   12 эп  Yuru Yuri San☆Hai!
19093  ova         2019  Осень 2019    1 эп  Yuru Yuri,
21401  ona         2019  Осень 2019    4 эп  Mini Yuri
```

⚠️ **Одного `<year>` не хватает**: у Season 3 год 2015, но в 2015-м ещё OVA (Зима) и tv_special (Лето).
Спасает именно квартал из `<premiered>` + `type` + число серий.

Локальный `Specials/S00E01 - Love Paradox Eternal` при этом красиво садится на id 9888
(`…Paradox, Eternal`) — подтверждение, что правило работает и для спешлов.

### C2. Если `season.nfo` нет
Подбор по шаблонам от базового названия: `{base} 2nd Season`, `{base} Season 2`, `{base} II`,
`{base} Revenge`, `{base}♪♪`, `{base} San☆Hai!`… с тем же fuzzy-порогом.

### C3. Слабый сигнал — `<plot>` из `season.nfo`
Часто содержит родное название сезона: в Season 2 у YuruYuri в тексте прямо стоит «Yuru Yuri♪♪».
Используется только для разрешения ничьей между равными кандидатами.

Связей «сиквел/приквел» в API **нет**, поэтому при неуверенности — «предложение» или ручной маппинг.

## Каскад D — ручной маппинг

Всё, что не прошло A–C, попадает на страницу «нераспознанные папки». Ручная привязка помечается
`is_manual = true` и **никогда не перетирается** последующими автоматическими сканами.

---

## Модель данных маппинга

**Many-to-many.** Одна папка может дать несколько `series_id` (по сезонам), один `series_id` может
лежать в нескольких папках.

У каждой связи хранится:
- `source` ∈ `anilist_id | mal_id | original_title | exact_title | fuzzy | premiered | manual`
- `confidence` (числовая оценка)
- `matched_on` — на какую именно строку/ID сматчилось

Это нужно, чтобы:
1. в UI на странице тайтла показать плашку «смаппился на папку X по названию Y из `.nfo`» —
   пользователь сразу видит ошибку;
2. на карточке каталога показать значок проблемного маппинга;
3. после первого прогона получить **отчёт по распределению `source`** и понять, где алгоритм слаб.

## Маппинг эпизодов

### Приоритет 1 — эпизодный `.nfo`
`<season>`, `<episode>`, `<title>`. Надёжнее любого парсинга имени.
Спешлы отсекаются по `<season>0</season>`, а не эвристикой.

### Приоритет 2 — парсинг имени файла
Для папок без `.nfo` (например `[Ohys-Raws] Yuru Camp Season 2 (BD 1280x720 x264 AAC)`).
Правила — в `config/filename_rules.yaml`, см. [03-architecture.md](03-architecture.md).

### Языки сайдкар-субтитров
По суффиксу: `.ru.` → ru · `.ja.`, `.jpn.` → ja · `.en.`, `.eng.` → en.
Голый `.srt`/`.ass` без языка → «неизвестный», показываем отдельно, не считаем ни за один язык.

Реальный пример неконсистентности (папка `Watashi wo Tabetai, Hitodenashi`): рядом лежат
`….srt`, `….ru.srt` — первый без языка. И в `Neon Genesis Evangelion - Death and Rebirth`:
`.jpn.srt`, `.ja.srt`, `.3.ja.srt`, `.1.ja.srt` — то есть встречаются и числовые префиксы.

### Вшитые дорожки
Из `<fileinfo><streamdetails>` эпизодного `.nfo` — там уже есть `<subtitle><language>` и
`<audio><language>`. Бесплатно, без ffprobe.
⚠️ Данные не идеальны: у Fate HF I у **видео**дорожки стоит `language: ita` — явная ошибка Jellyfin.
Поэтому считаем подсказкой, а не истиной.

### Число серий
```
total = max(numberOfEpisodes, кол-во tv-эпизодов в API, максимальный локальный номер)
```
Если локально 25, а сайт говорит 22 из 24 — показываем 25.

### Что игнорируем
`Specials/`, `S00E*`, `NCOP|NCED|OP\d|ED\d|PV|Trailer|SP`, а также «левые» большие номера
(эпизод > `numberOfEpisodes` × 1.5 и не подряд). По ТЗ — просто игнор, но с пометкой `unmatched`,
чтобы это было видно в UI, а не потерялось молча.

## Эталонные папки для проверки

| Папка | Чем интересна |

## Проход после каскадов: контейнер против подпапки

Маппинг считается по каждой папке независимо, поэтому один тайтл может получить две привязки.
Случай не редкий, а системный: `<anilistid>` из `tvshow.nfo` указывает на первый сезон, папка
`Season 1` наследует ID родителя — и он остаётся у обоих.

`_drop_container_duplicates()` снимает привязку с корня, но только когда есть потомок с файлами:
у корня нет своих видео, у потомка видео есть.

Исключения для спешлов нет — решение пользователя. При раскладке «корень без видео + только
`Specials`» привязка уедет на `Specials`, и туда же пойдут загрузки, пока не появится папка
сезона с файлами.

Раскладки, которые обязаны продолжать работать:

| Раскладка | Что происходит |
|---|---|
| `Show/` (0 видео) + `Show/Season 1` (12) | корень уступает сезону |
| `Show/` (12 видео), подпапок нет | ничего не меняется, привязка одна |
| `Show/` (5 видео) + `Show/Season 1` (12) | обе остаются, основную выбирает ranking |
| `Show/` (0 видео) + только `Show/Specials` | корень уступает `Specials` |
| `Show/` (0 видео) + пустая подпапка | корень сохраняется |
| ручная привязка на корне | не трогается никогда |
