# Безопасность

Ответ на вопрос из ТЗ (INF-05): **выставлять это наружу без авторизации нельзя.**
Ниже — конкретные риски и меры, а не общие слова.

## Итоговая рекомендация

Биндить на `127.0.0.1` или в локальную сеть, доступ через VPN (Tailscale/WireGuard).
Если всё же через Nginx наружу — внешняя аутентификация (Authelia / basic auth) **плюс**
встроенный пароль как второй рубеж, HTTPS, rate limiting, fail2ban.

---

## 1. Утечка premium-токена

**Риск.** `access_token` бессрочный (до смены пароля). Страница настроек или любой прокси-эндпоинт
дают к нему доступ. Украденный токен = чужой доступ к вашей подписке.

**Меры**
- токен **никогда** не отдаётся в API-ответах — только маска `f1e4…2cbf` и флаг `is_set`;
- подстановка токена только на сервере, в браузер он не попадает вообще;
- отдельный эндпоинт «проверить токен» вместо «показать токен»;
- фильтр-редактор логов: подстрока токена вырезается из всех логов и текстов ошибок
  (иначе он утечёт в трейсбек при первом же сбое CDN).

## 2. SSRF и «вирусный base_url» — главный класс

Это то, про что спрашивал пользователь: правка DOM или тела запроса в браузере не должна ничего
решать. Принцип — **клиент не является источником истины, валидация только на сервере**.

**Меры**
- `base_url` — не свободная строка, а **выбор из серверного allowlist**
  (`smotret-anime.app|org|online|net`), заданного в коде/ENV. С фронта приходит значение, сервер
  сверяет со своим списком и при несовпадении отвечает `400`. Новое зеркало добавляется только
  через ENV/конфиг на сервере, из UI — никак;
- схема только `https`, порт только дефолтный;
- запрещены IP-литералы, `localhost`, `.local`, `169.254.*`, `10.*`, `172.16–31.*`, `192.168.*`;
  проверка **после DNS-резолва**, иначе обход через DNS-rebinding;
- хосты CDN, куда ведёт `302`, сверяются с паттерном (`*.quantum-phantom-moon.ru`, `*.b-cdn.net`) —
  редирект не ведём куда попало;
- **никаких** открытых прокси-эндпоинтов вида `/fetch?url=…`;
- то же касается `jellyfin_url` при включённой интеграции.

## 3. Запись в ФС и path traversal

**Риск.** Ручной маппинг и постобработка принимают пути от пользователя. `../../etc` или симлинк
наружу = запись куда угодно от имени контейнера.

**Меры**
- путь нормализуется и проверяется как потомок настроенного корня: `Path.resolve()` +
  `is_relative_to(root)`, причём **после** разыменования симлинков;
- запрещены `..`, абсолютные пути вне корней, NUL-байты;
- имена файлов санитизируются: вырезаются `/ \ : * ? " < > |`, управляющие символы, `[` `]`,
  хвостовые точки и пробелы; проверка на зарезервированные имена Windows (`CON`, `PRN`, `AUX`,
  `NUL`, `COM1…9`, `LPT1…9`) — библиотека может лежать на SMB-шаре;
- лимит длины имени (**в байтах**, UTF-8 многобайтовый) и полного пути;
- ⚠️ отдельно важно: `authorsSummary` приходит **с внешнего сайта** и попадает в имя файла —
  это недоверенный ввод, санитизация обязательна (см. [06-naming-rules.md](06-naming-rules.md)).

## 4. SQL-инъекции

**Меры**
- только SQLAlchemy с параметризованными запросами; сырой SQL — исключение, и там только
  bound-параметры, никакой конкатенации строк;
- ⚠️ отдельная осторожность с **FTS5**: пользовательская строка поиска **не** склеивается
  в `MATCH`-выражение, а передаётся параметром и экранируется. Иначе кавычки и операторы FTS
  (`*`, `NEAR`, `OR`, `"`) ломают запрос или дают неожидаемую выборку.

## 5. XSS

**Риск.** Описания тайтлов, названия, имена авторов приходят с внешнего сайта.

**Меры**
- React экранирует по умолчанию; `dangerouslySetInnerHTML` **запрещён** — описания рендерим текстом;
- CSP без `unsafe-inline`;
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.

## 6. CSRF

**Меры**
- сессионная кука `HttpOnly` + `SameSite=Strict` + `Secure`;
- изменяющие операции только `POST/PUT/DELETE` — никаких мутаций по `GET`;
- проверка `Origin` / `Sec-Fetch-Site`.

## 7. Брутфорс пароля

**Меры**
- пароль хранится как argon2 (или bcrypt) хеш, не в открытом виде;
- лимит попыток по IP + задержка;
- сравнение в константное время;
- секрет подписи сессий генерируется при первом старте и сохраняется в `config/` — **не хардкод**;
- если пароль не задан — вход открыт, но UI показывает заметное предупреждение.

## 8. Заполнение диска и DoS

**Риск.** Батч «скачать все видео» на тайтле с 300 сериями — десятки ГБ (1080p ≈ 229 МБ/серия).

**Меры**
- лимит длины очереди;
- проверка свободного места перед стартом задачи + порог `min_free_space_gb`;
- лимит размера тела запроса;
- rate limit на дорогие эндпоинты (онлайн-поиск, `embed`, батч-постановка).

## 9. Использование вашего премиума как чужого прокси

**Меры** — авторизация обязательна; CDN-ссылки не отдаются анонимно; эндпоинт плеера тоже под сессией.

## 10. Docker

**Меры**
- медиатома монтировать точечно, `:ro` где можно (корням библиотек rw нужен только для записи
  результатов);
- non-root, PUID/PGID;
- `no-new-privileges: true`, `cap_drop: [ALL]`;
- `read_only: true` для rootfs + tmpfs на `/tmp`;
- **никакого** `network_mode: host`;
- порт публиковать как `127.0.0.1:8080:8080`, если снаружи Nginx.

## 11. Цепочка поставок

Пины версий зависимостей, `pip-audit` и `npm audit` в сборке.

## Негативные тесты (обязательны на этапе 6)

| Тест | Ожидание |
|---|---|
| Подменить `base_url` на посторонний хост через правку тела запроса | `400`, запрос наружу не уходит |
| Подменить `base_url` на `http://192.168.1.1` | `400` |
| Путь с `..` в ручном маппинге | отказ |
| Симлинк из папки библиотеки наружу как цель | отказ |
| Поиск со строкой `" OR 1=1 --` и с FTS-операторами | запрос не ломается, выборка пустая/корректная |
| Имя автора с `../` и `:` в нём | попадает в имя файла санитизированным |
| Проверить все ответы API и логи на наличие токена | токен не встречается ни разу |
| Мутация через `GET` | не существует |
