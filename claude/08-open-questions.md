## Не выяснено про API

| # | Вопрос | Почему не выяснено |
|---|---|---|
| 1 | Живут ли подписанные ссылки `?m=…&r=…` дольше одного обращения | Повторный GET отдавал 0 байт и на прокси, и на Bunny. Похоже на одноразовость, но точный TTL не измерен. **Практическое следствие уже учтено**: воркер запрашивает `embed` заново непосредственно перед скачиванием |
| 2 | Реальная разница скорости прямого Bunny-хоста на видео | Замер на тестовом файле дал 5.6×, но на видео воспроизвести не удалось (см. выше), и мерялось не из сети пользователя. Проверяется тогглом на месте |
| 3 | Есть ли на самом деле rate limit у API | При ~60 запросах в минуту не сработал. Ограничитель в клиенте всё равно ставим |
| 4 | Что в аккаунте на сайте даёт настройка выбора CDN | `/diagnostic` требует сессионную куку, программно недоступен. Через API настройка не видна |
| 5 | Полный список значений `episodeType` и `qualityType` | Видели `tv, movie, ova, ona, special, preview`. Обрабатываем известные, неизвестные — в `unmatched` с логом, а не падение |
| 6 | Всегда ли `subtitlesVttUrl` присутствует у софтсабов | Встречался не у всех. Опираемся на `subtitlesUrl`, VTT — необязательный бонус |

## Известные слабые места будущей реализации

| # | Место | Суть |
|---|---|---|
| 1 | **Маппинг сезонов без `season.nfo`** | Если `season.nfo` нет, остаются только шаблоны названий (`2nd Season`, `♪♪`, `Revenge`…). Связей «сиквел/приквел» в API нет вообще, поэтому часть уйдёт в ручной маппинг. Это принципиальное ограничение, не лень |
| 2 | **`movie` внутри сериала** | 115 тайтлов имеют `type=movie` при `numberOfEpisodes>1`. Автоматически надёжно не развести «связка фильмов» vs «сериал» → переключатель в UI с запоминанием |
| 3 | **Хардсаб и точные ступени качества** | Только через `embed`, 1 запрос на перевод, а у тайтла бывает ~2000. Отсюда ленивость и «оценочная» сводка качества. Полная точность требует N запросов и кнопки «уточнить» |
| 4 | **Правки существующих тайтлов** | У series нет `updatedDateTime` → ловятся только полным рескaном раз в сутки. Если на сайте поправят название, узнаем не сразу |
| 5 | **`streamdetails` из `.nfo` не идеальны** | У Fate HF I у видеодорожки стоит `language: ita` — явная ошибка Jellyfin. Используем как подсказку, не как истину |
| 6 | **Встроенный плеер и кодеки** | `<video>` + ASS через JASSUB покрывает не всё (HEVC в браузере, экзотические контейнеры). Поэтому ссылка на страницу сайта делается **всегда**, как надёжный фолбек |
| 7 | **Имена файлов на SMB** | Если библиотека на SMB-шаре, ограничения жёстче (хвостовые точки, зарезервированные имена). Санитизация это учитывает, но вживую не проверено |

## Отложенные идеи (P3+, за пределами текущего объёма)

| Идея | Комментарий |
|---|---|
| Отметки «просмотрено» / синк списков | Через Anime365 **невозможно** — эндпоинтов нет. Реально только прямая интеграция с API Shikimori или AniList: свой OAuth, свои токены, отдельный объём |
| Автоскачивание новых серий онгоингов | Полу-Sonarr: следить за `isAiring` тайтлами из «моих» и качать новые серии выбранных переводчиков. Требует понятия «подписка на тайтл + автора» |
| Конвертация ASS → SRT | Пользователь выбрал хранить `.ass`. Может понадобиться, если какой-то внешний плеер по Jellyfin API не тянет ASS |
| Дедупликация переводов по качеству | Если один автор выложил и 720, и 1080 — предлагать заменить локальный файл на лучший |
| Импорт `scan_results.csv` | См. вопрос 2 выше |
| Уведомления по завершении батча | Webhook / Telegram |
| Аккаунты пользователей | Схема готова ([D-09](09-decisions.md)), включение = логины вместо общего пароля |
