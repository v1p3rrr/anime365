### Про фильтр по типу перевода — проверено, данных нет

`chips`-фильтры по типу перевода API **игнорирует**: `subtitles@=subJa`, `translation@=subJa`,
`voice@=1` и подобные возвращают ту же выдачу, что и запрос без них. В объекте тайтла из полей
про переводы есть только `fansubsId`.

Значит, чтобы фильтровать каталог по наличию японских субтитров, нужно знать переводы каждого
тайтла. Один запрос на тайтл — это **29 231 запрос**, при ограничителе 5 запросов в секунду
примерно **1,5–2 часа**.

Хранить все переводы целиком нельзя: у Frieren их около 2000, в среднем по каталогу выйдет
порядка двух миллионов строк. Но можно хранить **только сводку по тайтлу** — какие пары
«язык + тип» существуют и сколько переводов в каждой. Это 29 тысяч строк с маленьким JSON.

Предложение: отдельная фоновая задача «собрать сводку переводов по каталогу», запускается
вручную, идёт часами в фоне, показывает прогресс. После неё фильтры работают. Требует решения
пользователя, потому что это заметная нагрузка на API.

## 3. Не выяснено про API

| # | Вопрос | Почему не выяснено |
|---|---|---|
| 1 | TTL подписанных ссылок `?m=…&r=…` | Повторный GET отдавал 0 байт и на прокси, и на Bunny. Похоже на одноразовость. **Практически учтено**: воркер запрашивает `embed` заново перед каждой загрузкой |
| 2 | Реальная скорость прямого Bunny-хоста на видео | На тестовом файле 5.6×, на видео замер не воспроизведён, и мерялось не из сети пользователя. Проверяется тогглом на месте |
| 3 | Есть ли у API rate limit | При ~60 запросах в минуту не сработал. Ограничитель в клиенте всё равно стоит |
| 4 | Что даёт настройка CDN в аккаунте на сайте | `/diagnostic` требует сессионную куку, программно недоступен |
| 5 | Полный список значений `episodeType` и `qualityType` | Видели `tv, movie, ova, ona, special, preview`. Неизвестные попадают в `unmatched` с логом, а не роняют скан |
| 6 | Заполнен ли `isHentai` хоть у кого-то | В списочном ответе нулевой у всех 29 231. Фильтр реализован, но ничего не отсекает |

## 4. Известные слабые места (принципиальные, не лень)

| # | Место | Суть |
|---|---|---|
| 1 | **Сезоны без `season.nfo`** | Остаются только шаблоны названий. Связей «сиквел/приквел» в API нет вообще, поэтому часть уйдёт в ручной маппинг |
| 2 | **`movie` внутри сериала** | 115 тайтлов имеют `type=movie` при `numberOfEpisodes>1`. Автоматически «связку фильмов» от сериала не отличить → нужен переключатель в UI (TTL-02, не сделан) |
| 3 | **Хардсаб и точные ступени качества** | Только через `embed`, один запрос на перевод, а их бывает ~2000. Отсюда ленивость и «оценочная» сводка качества |
| 4 | **Правки существующих тайтлов** | У series нет `updatedDateTime` → ловятся только полным рескaном раз в сутки |
| 5 | **`streamdetails` не идеальны** | У Fate HF I у видеодорожки стоит `language: ita`. Используем как подсказку, не как истину |
| 6 | **Кодеки во встроенном плеере** | HEVC в браузере покрыт не везде. Поэтому ссылка на сайт делается всегда, как надёжный фолбек |
| 7 | **Имена на SMB** | Санитизация учитывает зарезервированные имена и хвостовые точки, но вживую на шаре не проверялась |
| 8 | **1.7% имён не разбирается** | 38 файлов из 2284: бонусы с дисков, сцен-каты с китайскими названиями. Правила дописываются в YAML без пересборки |

## 5. Отложенные идеи (за пределами текущего объёма)

| Идея | Комментарий |
|---|---|
| Отметки «просмотрено» / синк списков | Через Anime365 **невозможно**: эндпоинтов нет. Только прямая интеграция с Shikimori или AniList — свой OAuth, отдельный объём |
| Автоскачивание новых серий онгоингов | Полу-Sonarr: следить за `isAiring` из смапленных и качать новые серии выбранных переводчиков. Нужно понятие «подписка на тайтл + автора» |
| ffprobe за тогглом | Сужен до файлов без `<streamdetails>`, по кнопке. Массовый прогон не делаем |
| Jellyfin API | Сужен до одной операции: пинок «пересканируй папку» после раскладки файлов |
| Конвертация ASS → SRT | Пользователь выбрал хранить `.ass`. Может понадобиться, если внешний плеер не тянет ASS |
| Дедупликация по качеству | Если автор выложил и 720, и 1080 — предлагать заменить локальный файл |
| Уведомления по завершении батча | Webhook / Telegram |
| Аккаунты пользователей | Схема готова ([D-09](09-decisions.md)): `app_user`, `created_by_user_id`, клиентские настройки под версионированным префиксом |
| Размер папок в каталоге | Считается при скане, в карточках не выводится |
| Значки озвучки по языкам | **Нет данных.** У видеофайла роль всегда `video`: при сопоставлении язык дорожки не сохраняется, `SUB_ROLE` разводит по языкам только субтитры. Нужны роли вида `video_ru` / `video_en`, а это меняет словарь ролей во всём подсчёте покрытия и в подписях UI. Тоггл без данных был бы обманом, поэтому его нет |

## 6. Запланировано, но не начато

### Скачивание только звуковой дорожки

Отдельная фича, поставленная пользователем 2026-07-30. Реализуется **после** текущих задач.

**Зачем.** Нужна отдельная фонотека: озвучка или оригинальная японская дорожка без видео.

**Как задумано.**
1. Берём уже скачанное видео либо качаем его специально.
2. Достаём дорожку `ffmpeg`-ом — без перекодирования, копированием потока
   (`-c:a copy`), иначе теряется качество и тратится процессор.
3. Кладём результат в **отдельный корень**, не в основную библиотеку: это не то,
   что должен индексировать Jellyfin как видео.

**Что нужно решить до реализации:**

| Вопрос | Почему важен |
|---|---|
| Отдельная настройка пути (`audio_root`) | Каталог не библиотечный, под правило «потомок корня библиотеки» не подходит — нужен свой корень и своя проверка пути |
| Судьба исходного видео | Удалять после извлечения, оставлять или качать во временную папку и не класть в библиотеку вовсе — три разных сценария |
| Контейнер и расширение | Дорожка бывает AAC, FLAC, Opus. `-c:a copy` требует контейнера, который её примет: `.m4a` для AAC, `.mka` универсально |
| Выбор дорожки при нескольких | У raw-релиза бывает несколько аудиопотоков; нужен выбор по языку из `streamdetails` или из `ffprobe` |
| ffmpeg в образе | Сейчас его нет. Это +70 МБ к образу; возможно, ставить только при включённом тоггле не выйдет — значит, решаем, тащить ли всегда |
| Именование | Правила из [06-naming-rules.md](06-naming-rules.md) писались под видео и сайдкар-субтитры; для фонотеки нужна своя схема |

Отдельная задача в списке; в матрицу фич добавится, когда дойдёт до реализации.
