Приложение умеет: показывать каталог из 29 231 тайтла с поиском и фильтрами, открывать
страницу тайтла со сводкой переводов, сканировать библиотеку и сопоставлять папки с тайтлами
(включая разведение сезонов), скачивать видео и субтитры с правильным именованием, показывать
очередь с живым прогрессом, смотреть серии прямо в браузере, извлекать звуковую дорожку в
фонотеку, редактировать настройки из UI.

Вход — по логину и паролю; главная учётная запись задаётся окружением
(`A365_ADMIN_LOGIN` + `A365_UI_PASSWORD`), остальные заводятся в интерфейсе. Прав
пять: каталог, просмотр, загрузки, библиотека, настройки. **Каждый** эндпоинт под
`/api/` спрашивает право (открытых шесть, все объяснены), а интерфейс не рисует
того, на что прав нет — таблица в [docs/admin.md](../docs/admin.md), решение и
границы в [D-76](09-decisions.md).

Панель загрузки серии предлагает в первую очередь то, чего нет локально: что считать
недостающим, решает язык звуковой дорожки уже скачанного видео ([D-44](09-decisions.md)).
Интерфейс переведён на три языка и умеет светлую тему.

Проверено на реальных данных: 2284 видеофайла разобрано (1.7% не распознано), маппинг 12/12 на
эталонных папках, скачано настоящее видео 87.7 МБ с валидной сигнатурой `ftyp isom`.
Образ собирается, контейнер поднимается healthy. Тестов **820**.

## Что это за проект

Приложение для домашнего сервера: смотреть каталог Anime365, качать видео и субтитры по
премиум-API, раскладывать в существующую Jellyfin-библиотеку с правильными именами и маппингом
на уже скачанное.

- Библиотека: `~/media/anime/library/*` (сериалы), `~/media/anime_movies/library/*` (фильмы)
- Смотрится через Jellyfin, рядом планируются Sonarr/Radarr/qBittorrent
- Целевая платформа — **Ubuntu Server** в Docker; сервер слабый (16 ГБ ОЗУ)
- Интересующие языки: **ru, en, ja**, остальные игнорируются
- Библиотеку планируется монтировать **только для чтения** на время первых прогонов

## Стек

Python 3.12 + FastAPI + SQLite(WAL) + SQLAlchemy 2.0 + APScheduler + httpx + watchdog ·
React 18 + TypeScript + Vite + Mantine + TanStack Query/Virtual · один Docker-образ, один порт.

## 🔴 Главное, что нельзя забыть

1. **Секреты не коммитим.** Токен бессрочный, попавший в историю остаётся навсегда.
   Правило №0 в [07-security.md](07-security.md). Проверять `git status` перед каждым push.
2. **`temp/` в `.gitignore`** — там личные данные пользователя, но это и **эталон для
   проверки**: две настоящие папки с `.nfo` и файлами (13 ГБ) плюс выгрузки `tree.txt`
   на 11 364 строки. Что чем проверяется — в [docs/developer.md](../docs/developer.md).
3. `GET /api/series` **без `fields` отдаёт всё**, включая эпизоды и описания.
4. `embed` всегда возвращает ссылки на `smotret-anime.org` → нужен rewrite хоста.
5. Пагинация переводов — **только `feed=id` + `afterId`**, иначе выдача врёт.
6. Хардсаб определяется только через `embed` (`subtitlesUrl == null`) → лениво, с кэшем.
7. `numberOfEpisodes` — это план, а не выложенное. Локально серий может быть больше.
8. Всё с Anime365 помечается **`WEBDL`**, даже если соседи `Bluray`. Но у субтитров к
   существующему видео basename берётся **как есть** — иначе Jellyfin их не подхватит.
9. Отметок «просмотрено» в API **нет вообще**.
10. Скачать 4K нельзя: потолок ступеней — 1080, даже у 2160-источников.
11. `weight` во франшизе Шикимори — **не порядок просмотра**. Проверено на данных: у фильма
    2025 года `weight: 1`, а сериал 2018-го последний. Порядок — топологический по
    `sequel`/`prequel`.
12. **Четыре корня библиотек не пересекаются**, иначе контейнер не стартует. Проверка стоит и
    при старте, и при сохранении настроек — путь из `docker-compose` до эндпоинта не доходит.
13. Ошибка Anime365 может прийти **в теле ответа с HTTP 200** — код смотрится в payload,
    а не только в статусе.
14. Новая колонка не заполняется у существующих строк сама: `add_missing_columns()` дописывает
    колонку, дефолт модели применяется при вставке. Роль `is_admin` уже на этом обжигалась.
15. **Индексы тоже не появляются сами** — `create_all` делает их только вместе с новой таблицей,
    а индекс с уже занятым именем не переопределяет вовсе. За существующие базы отвечает
    `sync_indexes()`: она создаёт недостающие и пересоздаёт изменившиеся. Цена пропуска: каталог
    отвечает секунду вместо миллисекунды, и заметить это можно только замером
    ([D-81](09-decisions.md)).
16. **Таблица `series` широкая** (~25 МБ на 29 тысяч строк из-за JSON-колонок). Любое обращение
    к строке стоит секунду, поэтому запросы каталога обязаны идти по **покрывающим** индексам:
    в индексе с нужным порядком сортировки лежат и все фильтруемые колонки, а сам индекс
    называется явно через `INDEXED BY` — планировщик при равной цене выбирает по-разному на
    разных версиях SQLite ([D-84](09-decisions.md)). Закреплено `test_catalog_indexes.py`
    (60 сочетаний фильтров и сортировок).
16а. **`rowid` в `series_fts` — это `series.id`.** Читать колонку `series_id` в сто раз дороже
    (243 мс против 2,4 мс на 7525 совпадениях), а `ORDER BY rank` считает BM25 по всем
    совпадениям сразу.
17. **Долгая пишущая транзакция = «database is locked» у всех остальных.** Писатель у SQLite
    один, `busy_timeout` 10 с. Сетевые вызовы и тяжёлые вычисления — только вне транзакции
    ([D-80](09-decisions.md)), это сторожат `test_db_locking.py` и `test_transaction_hygiene.py`.
