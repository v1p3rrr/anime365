# Требования (из ТЗ пользователя)

Пронумерованы, чтобы на них ссылаться в коде, коммитах и [04-feature-matrix.md](04-feature-matrix.md).
Формулировки — пересказ ТЗ, а не дословная копия.

## Контекст и экосистема

| ID | Требование |
|---|---|
| CTX-01 | Standalone-приложение для домашнего сервера, качает аниме и субтитры по открытому API Anime365 |
| CTX-02 | Возможность выбора `base_url` — у Anime365 несколько зеркал |
| CTX-03 | Библиотека уже существует и жёстко разделена: сериалы и фильмы в разных корнях |
| CTX-04 | Смотрится через Jellyfin (сабы на разных языках) + внешние плееры по Jellyfin API → в папках могут лежать метафайлы |
| CTX-05 | В перспективе рядом Sonarr/Radarr/qBittorrent; часть библиотеки скачана ими с другого компа и адаптирована под Jellyfin → возможны неконсистентности имён и разбиения по папкам |
| CTX-06 | Интересующие языки — **только ru, en, ja**. Остальные игнорируются |
| CTX-07 | Сервер слабый (16 ГБ ОЗУ, низкая частота) → код лёгкий, но безопасный и поддерживаемый |

## 2. Страница тайтла и переводы

| ID | Требование |
|---|---|
| TTL-01 | Переход на страницу тайтла: описание, постер, все варианты названий на разных языках, список серий/фильмов |
| TTL-02 | Учесть, что фильмы могут быть помечены как сериал (2–3 связанных фильма); обычно у них свой ID, но не всегда |
| TTL-03 | Для каждой серии — список переводов, визуально разделённый по языкам и по типу (озвучка/субтитры) |
| TTL-04 | Для субтитров понятно: вшиты в видео или отдельный скачиваемый файл |
| TTL-05 | Сводный раздел над всеми сериями: переводы за весь тайтл, сгруппированные по языкам и типам |
| TTL-06 | В сводке — авторство (студия/команда) и покрытие серий («на все серии» или «с 1 по 19, с 22 по 25») |
| TTL-07 | Переводы спрятаны под кат/спойлер (10 озвучек × 20 сабов на серию не должны вываливаться), причём эффективно для рендера |
| TTL-08 | Кнопка Play: встроенный веб-плеер с подтягиванием видео и файла сабов **или** ссылка на страницу серии на сайте |
| TTL-09 | Галка в UI, чтобы не отображать кнопки и инфо по ненужным языкам; все три одновременно выключить нельзя |
| TTL-10 | Сводка с общей инфой по наличию (аналогично значкам на постерах) |
| TTL-11 | Учитывать тип эпизода (ona/ova/special/movie) и то, попадает ли он под понятие фильма/сериала в Jellyfin/Sonarr/Radarr *(добавлено позже)* |
| TTL-12 | Плашка маппинга: на какую папку и на какое название из `.nfo` смаппился тайтл — чтобы видеть ошибку *(добавлено позже)* |

## 3. Загрузки, маппинг, постобработка

| ID | Требование |
|---|---|
| DL-01 | Точечная загрузка по клику на конкретный перевод |
| DL-02 | Батч-кнопки в сводном меню тайтла: «все сабы отдельными файлами», «все видео», «видео + сабы» |
| DL-03 | При запуске стартует джоба; загрузки становятся в очередь (БД или файл — на усмотрение) |
| DL-04 | Пайплайн: скачать во временную папку → переименовать → переместить в папку аниме или создать новую |
| DL-05 | Из имени убрать релиз-группу раздающего и заменить на `anime365_{название группы перевода}` |
| DL-06 | Механизм ретраев при падении загрузки |
| DL-07 | Страница очереди в UI: прогресс, ручной ретрай, пауза конкретного файла и всей очереди |
| DL-08 | Индикатор работы джобы обработки скачанных файлов |
| DL-09 | Языковые суффиксы: сабам `.ru`/`.ja`/`.en`; японскому оригиналу к видео ничего; ru/en-озвучке — `.ru`/`.en` перед расширением |
| DL-10 | Сканирование папки и подсветка недостающих видео/субтитров на странице тайтла, с сообщением сверху |
| DL-11 | Если локально серий больше, чем показывает сайт — пишем локальное число; корректно мапить их друг на друга |
| DL-12 | Отдельный модуль маппинга, алгоритм выводится из файловой структуры, имён и данных API; индикатор работы джобы сканирования |
| DL-13 | Ручной маппинг тайтла на папку: добавить/удалить/изменить |
| DL-14 | Ручной перемап пути у каждого отдельного эпизода |
| DL-15 | Игнорировать «левые» серии (странные имена, большие номера, необработанные, спешлы/OVA) — пока просто игнор |
| DL-16 | Кнопка загрузки по умолчанию 1080 + выпадашка доступных ступеней (720/360/…); у некоторых бывает только 360 *(добавлено позже)* |
| DL-17 | В сводке — информация о доступном качестве: «все эпизоды в 1080» либо мин. качество по диапазонам серий *(добавлено позже)* |
| DL-18 | Батч-загрузка видео: «максимум до 1080» либо конкретное качество с фолбеком на максимальное доступное ниже *(добавлено позже)* |
| DL-19 | Всё с Anime365 помечать как `WEBDL`, даже если соседние эпизоды `Bluray` *(добавлено позже)* |
| DL-20 | Парсер имён файлов — гибкий/расширяемый механизм, чтобы дописывать правила по присланному списку файлов *(добавлено позже)* |

## 4. Настройки

| ID | Требование |
|---|---|
| CFG-01 | Base URL |
| CFG-02 | API-ключ (аккаунт с премиум-подпиской) |

| CFG-07 | Обновление кэша каталога: по умолчанию раз в час, значение в часах задаётся в настройках *(добавлено позже)* |

## 5. Инфраструктура

| ID | Требование |
|---|---|
| INF-01 | `Dockerfile` + `docker-compose.yml`; сервисы лежат каждый в своей папке с композом, рядом папка с данными/конфигами |
| INF-02 | Медиа-папки прокидываются в контейнер с другого диска |
| INF-03 | Возможность поставить контейнер в одну сеть с другими сервисами |
| INF-04 | UI по IP:port, возможно через Nginx наружу |
| INF-05 | **Ответить на вопрос:** насколько это безопасно для сервера и локалки; рассмотреть все риски |
| INF-06 | Backend: Python предпочтительнее, если немного кода и слабая связанность (Java/Spring/Kotlin — знакомы, но тяжелы) |
| INF-07 | Frontend на усмотрение, желательно TypeScript, с нормальными UI-библиотеками и хорошим UX |
| INF-08 | БД: решить как эксперт — SQLite или PostgreSQL |
| INF-09 | Документация: пользовательская, админская и разработческая (архитектура, тонкие нюансы, что не доведено до ума и почему) |
| INF-10 | Учесть одновременную работу 2–3 человек; аккаунтов пока не делаем, но архитектуру подстроить так, чтобы добавить их без боли *(добавлено позже)* |
| INF-11 | Динамические элементы в UI не должны вылезать за пределы своего пространства или прятаться — вёрстка с расчётом на максимум элементов *(добавлено позже)* |
| INF-12 | Максимум проверок и санитизации; prepared statements для SQL; нельзя подменить `base_url` правкой кода элемента в браузере *(добавлено позже)* |

## Ответы на вопросы, заданные в ТЗ

| Вопрос из ТЗ | Ответ | Где подробно |
|---|---|---|
| Есть ли пагинация в API? | Есть: `limit`/`offset`, но для больших списков только `afterId`. Для переводов — обязательно с `feed=id` | [02](02-api-findings.md) |
| Стоит ли кэшировать список в файл? | Да, но в SQLite, а не в файл: 29 231 тайтл, 32 МБ JSON, скан 32 с | [09](09-decisions.md) |
| Как делать пагинацию в UI? | Виртуализированный скролл по полному списку id | [09](09-decisions.md) |
| Можно ли взять базу Jellyfin? | Не нужно: `.nfo` рядом с файлами содержат и названия, и внешние ID, и список дорожек | [05](05-matching-algorithm.md) |
| Embed или ссылка на сайт для Play? | И то, и другое | [09](09-decisions.md) |
| SQLite или PostgreSQL? | SQLite (WAL) | [09](09-decisions.md) |
| Насколько безопасно выставлять наружу? | Без авторизации — нельзя; полный разбор рисков и мер | [07](07-security.md) |
| Можно ли влиять на выбор CDN? | Через API — нет. Прямой Bunny-хост — гипотеза за тогглом | [02](02-api-findings.md) |
| Есть ли в API отметки просмотренного / синк с Shikimori? | **Нет вообще** | [02](02-api-findings.md) |
| Что такое fuzzy-матчинг? | Сравнение строк «на похожесть» вместо «равно» | [05](05-matching-algorithm.md) |
| Зачем ffprobe и Jellyfin API? | Почти не нужны — роль сужена | [09](09-decisions.md) |
